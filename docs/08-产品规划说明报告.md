## 1. 红河同路是什么

一个微信小程序。游客在红河县的四个地方（迤萨路口、马帮侨乡森林公园、马帮古城、撒玛坝梯田）停好车后打开它，确认自己到了，花 3 分钟看一看、听一听这个地方的介绍，答 3 道题攒「同路分」。分数够了，就可以到现场柜台领一份县里准备的本地小礼品。每一站还会介绍这里出产的东西，喜欢可以直接下单寄回家，钱和订单落到本地合作社、手艺人手里。

县里有一个电脑上用的「运营后台」：介绍内容在这里录入、交给县文化馆、民宗局、文旅局审定后才能上线；礼品库存、柜台、店员在这里管；每天多少人来、看完多少、领了多少礼、卖了多少货，也在这里看。

一句话：**让路过的游客停下来、看得懂、带点东西走，县里看得见、管得住。**

产品名「红河同路」，副标题「各族同路走，好物一路带」。前半句是这条长廊讲的事：各族群众在同一片土地上来往、一起过日子；后半句是这条长廊带动的事：本地物产。

## 2. 为什么要做

### 2.1 县里的基本情况

| 项目 | 数字 | 说明 |
|---|---|---|
| 户籍人口 | 36.09 万 | 2025 年度县情 |
| 少数民族占比 | 96.89% | 其中哈尼族占 81.4%（29.39 万），全国最大的哈尼族聚居县 |
| 世居民族 | 5 个 | 汉、哈尼、彝、傣、瑶 |
| 华侨华人 | 1 万余人 | 分布在 18 个国家和地区，迤萨是有名的侨乡 |
| 撒玛坝梯田 | 1.6 万余亩、4300 多级 | 世界文化遗产红河哈尼梯田组成部分，2021 年 4 月评为国家 4A |
| 马帮古城 | 国家级文物保护单位 | 2025 年 1 月评为国家 4A |

### 2.2 现在遇到的实际问题

| 问题 | 现在的情况 | 小程序怎么解决 |
|---|---|---|
| 游客路过不停留 | 自驾游客从高速下来直接去下一个县 | 四个点都设在停车方便的访客点，停下来 3 分钟就能完成一站，还有礼品 |
| 看了也不懂 | 景点介绍牌字多、没人讲 | 每站 3–4 张卡片 + 3 分钟音频，没信号也能播；答题帮游客记住 |
| 想买买不到、带不走 | 不知道哪里有正宗的红米、茶叶、手工艺品 | 每站介绍这里的物产，能直接下单寄回家，商品写清是哪个村、哪个合作社 |
| 内容讲错有风险 | 民族、宗教、文物相关的说法一旦讲错，影响很大 | 所有内容必须经县文化馆、民宗局、文旅局（古城加文物部门）审定后才能上线，出问题可以一键下线 |
| 县里看不到效果 | 来了多少人、带动了多少消费，说不清 | 后台数据看板每天更新，按站、按月统计 |

### 2.3 政策依据（简要）

- 《中华人民共和国民族团结进步促进法》2026 年 7 月 1 日起施行：要求增进共同性、尊重差异性（第六条），各民族优秀传统文化都是中华文化的组成部分（第十三条），公共场合突出国家通用语言文字（第十五条），规范展陈和讲解内容（第三十条），网络平台发现违规内容要及时处置（第三十一条）。
- 州里对文旅的要求：旅居、研学、文创深度融合，健全联农带农机制。
- 县里：以马帮古城为夜间经济核心；沪滇协作、央企定点帮扶带来团购和研学客源。

## 3. 谁在用，他们心里想什么

### 3.1 六类使用者

| 谁 | 在哪用 | 他最关心 | 产品给他什么 |
|---|---|---|---|
| 自驾、周末游客（主要用户） | 停车场、景区里，手机上 | 别耽误行程、别被套路、带点东西回去 | 3 分钟一站、第一站就能领礼、能寄回家 |
| 旅居、房车客 | 森林公园营地 | 日常吃的山货能不能重复买、能不能自提 | 营地自提、一键再买一次 |
| 柜台店员 | 游客中心、观景台服务点、文创店 | 扫一下就知道能不能发、发哪一档，别出错 | 店员端：扫码、看结果、选礼品、确认 |
| 合作社、手艺人 | 村里、作坊里 | 订单说得清：谁买的、发什么、什么时候发、钱什么时候到 | 订单通知、填快递单号、月度对账 |
| 运营人员 | 办公室电脑 | 内容好录、库存好管、出问题能马上处理 | 运营后台 |
| 审定单位（文化馆、民宗局、文旅局、文物部门） | 办公室电脑或手机 | 不出错、改了什么看得清、能随时下线 | 审定中心：逐条审、写意见、留记录 |

另外，县领导可以开一个只看数据的账号，看数据看板。

### 3.2 游客在每一步心里想什么

做产品最容易犯的错，是按「我们想讲什么」来设计，而不是按「游客此刻在担心什么」来设计。下面这张表是游客在各个环节最常见的疑问，以及界面上怎么第一时间回答他。

| 环节 | 游客心里在想 | 界面怎么回答 |
|---|---|---|
| 第一次打开 | 这是什么？要不要注册？要不要钱？ | 首页顶部一句话说明；浏览、听音频都不用登录；全程不收费 |
| 点打卡 | 会不会一直定位我？ | 按钮下方写「只在点击时取一次位置」；隐私弹窗写明用途 |
| 开车时 | 能不能边开边打卡？ | 必须先选「我已停稳」或「我是乘客」；车还在走时提示「请停稳后再打卡」，不给打 |
| 山里没信号 | 打不了卡、听不了音频怎么办？ | 进山前提示下载离线包；没信号可以扫现场立牌上的码 |
| 看内容 | 要看多久？ | 站点页第一行写「约 3 分钟」 |
| 答题答错 | 会不会扣分？丢不丢人？ | 不扣分，先看讲解，看完还给 3 分；没有倒计时、没有排行榜 |
| 看到分数 | 分数能干嘛？能抵钱吗？ | 同路卡直接写「现在可领第二档」；分数页写明「不能提现，不能抵现金」 |
| 领礼前 | 现在领还是再走一站？领了还能换更好的吗？ | 写明「现在领是第二档，再走一站可领第三档，今年只能领一次」，让游客自己选 |
| 领礼时 | 要带什么？去哪领？ | 领礼码页写「请带证件原件」和可领柜台 |
| 买东西 | 是不是骗游客的高价货？ | 每件商品写清生产者、村寨、采收时间；只有一个价格，没有划线价和倒计时 |
| 买完 | 东西什么时候到？有问题找谁？ | 订单页显示发货状态和合作社联系方式、售后入口 |
| 问问题 | 问了会不会乱答？ | 问驮驮只回答审定过的问题，每个答案标来源；答不了就直接给柜台电话 |

这张表是评审界面的一把尺子：每个页面上线前，都要能回答它对应环节的那个疑问。

## 4. 产品由哪几部分组成

### 4.1 三个端

| 端 | 用在哪 | 谁用 | 做什么 |
|---|---|---|---|
| 游客端 | 微信小程序 | 游客 | 打卡、看内容、答题、领礼、买东西、问问题 |
| 店员端、合作社端 | 同一个小程序里，绑定身份后才出现 | 柜台店员、合作社 | 扫码发礼品；看订单、填快递单号 |
| 运营后台 | 电脑浏览器 | 运营人员、审定单位、柜台主管、领导 | 管内容和审定、管站点、管礼品、管商品订单、看数据 |

店员端和合作社端不单独做 App，放在同一个小程序里，按身份显示，省去下载和培训成本。

## 5. 六个闭环

「闭环」的意思是：一件事从开始到结束有人管、有记录，结束时的结果又能反过来改进开头。这个产品里有六个闭环，每个都要在一期跑通。

### 5.1 游客体验闭环

到达打卡 → 看内容 → 答题得分 → 盖章、升级称号 → 看到「再走一站可以领更好的礼」→ 去下一站。

结束的标志：游客领到礼品，或四站走满得到「长廊同心人」称号。改进依据：后台看到哪一站完成率低，就去改那一站的内容。

### 5.2 礼品闭环

后台设置礼品档位和各柜台库存 → 游客出示领礼码 → 店员扫码核对证件后发放 → 库存自动减少、记录写入后台 → 库存低于预警线时提醒柜台主管补货 → 补货后后台加库存。

结束的标志：每一份礼品都能查到发给了谁（脱敏）、在哪个柜台、哪个店员、什么时间。

### 5.3 带货闭环

游客在站点页看到这一站的物产 → 加心愿单或下单 → 统一收款 → 合作社收到订单通知（写明「买家在撒玛坝看完梯田后下单」）→ 合作社发货、填快递单号 → 游客收货、评价 → 评价审核后公开 → 游客再买一次 → 月底运营方和合作社对账结算。

结束的标志：合作社收到货款。改进依据：后台看哪一站带动的订单多、哪类商品复购高。

### 5.4 内容闭环

运营人员录入内容 → 县文化馆审民俗表述 → 县民宗局审民族政策和用语 → 县文旅局批准发布（古城内容加文物部门）→ 上线 → 游客点「我发现内容有误」或运营巡查发现问题 → 退回修改或一键下线 → 修改后重新审定 → 再上线。

结束的标志：每一条线上内容都有完整的审定记录；被下线的内容和相关题目同时下线，游客已得的分数保留。

### 5.5 问答闭环

游客问问驮驮 → 能在已审定的问答库里找到，就给答案和来源 → 找不到，就请游客问柜台，并把这个问题记下来 → 运营人员每周整理没答上的问题 → 写好答案交审定 → 审定通过后加入问答库。

结束的标志：没答上的问题越来越少。

### 5.6 数据闭环

小程序记录每一次打卡、看完、答题、领礼、下单 → 后台数据看板按站、按天汇总 → 每月出一份运营简报给领导 → 根据数据调整：内容、礼品档位、柜台库存、立牌位置、商品。

## 6. 游客端：八个模块

每个模块按同样的结构写：解决什么问题、从哪进来、一步一步怎么走、规则、出意外怎么办、后台对应管什么、记录哪些数据。

### M1 入口与首页

**解决什么**：游客第一次接触，要在几秒钟内明白这是什么、对自己有什么用、要不要钱。

**从哪进来**

| 入口 | 进来后看到 |
|---|---|
| 四个站点停车场、游客中心的立牌二维码（下称「现场立牌码」） | 直接打开这一站的打卡页 |
| 「红河马帮古城景区」公众号菜单 | 首页 |
| 朋友分享、微信搜索「红河同路」 | 首页或被分享的那一页 |
| 高速出口、加油站的宣传物料 | 首页 |

现场立牌码是最重要的入口：游客已经站在现场，扫码直接到这一站，不用找。

**链路**

| 步骤 | 游客看到 | 游客心里 | 系统做什么 |
|---|---|---|---|
| 1 打开 | 首页：顶部「红河同路 · 各族同路走，好物一路带」、一张大图、八个入口 | 这是什么？ | 不要求登录 |
| 2 看公告 | 一条公告：森林公园防火期请勿携带火种 | 有没有要注意的？ | 公告由后台发布，防火公告置顶不能关 |
| 3 看四站 | 四站长廊：四张卡片，写着每站讲什么、在哪停车 | 先去哪？ | 四站没有先后，任选 |
| 4 选一站 | 站点预览：停车点、今天是否开放、约 3 分钟、能得 30 分、这一站的物产 | 值不值得停？ | 未到现场可以看介绍，不能答题 |
| 5 到了 | 「到达打卡」按钮 | — | 进入 M2 |

**首页八个入口**：到达打卡、四站、同心石榴、问驮驮、领礼、一路好物、服务地图、研学团队（二期开放）。

**服务地图**：只标停车场、厕所、服务柜台、医疗点、充电桩，点一下用微信自带地图导航。产品本身不画路线、不做导航，避免把游客引到不安全的山路和田埂上。

**规则**

- 首页不放商业广告、不放外部链接；大图只放季节、县里正式发布的活动、开放提醒。
- 未登录时顶部显示「登录记分」，登录后才显示分数。
- 右上角「中 / EN」：一期英文只覆盖站名、安全提示、礼品规则。

**后台对应**：B4（公告、开放状态、立牌码）、B2（首页大图、站点介绍）。

**记录的数据**：打开次数、入口来源（立牌码 / 公众号 / 分享 / 搜索）。

### M2 到达打卡

**解决什么**：确认游客真的到了现场，同时不能让人在开车时操作手机，也不能一直定位游客。

**链路**

| 步骤 | 游客看到 | 游客心里 | 系统做什么 |
|---|---|---|---|
| 1 进入打卡页 | 这一站的插画、「你现在应该在：观景台停车场」 | 我停的地方对吗？ | 写游客真正站着的地方，不写景点大名 |
| 2 二选一 | 「我已停稳」「我是乘客」两个按钮，必须选一个 | 开车能打吗？ | 不选不能点下一步 |
| 3 点「我到了」 | 大圆按钮，下方小字「只在点击时取一次位置」 | 会不会一直定位我？ | — |
| 4 第一次使用 | 微信隐私弹窗：位置只用于确认到达 | — | 用户同意后才取位置 |
| 5 确认位置 | 按钮外圈一圈圈扩散，「正在确认位置…」 | — | 取一次位置，和这一站的打卡范围比对 |
| 6 成功 | 同路册上盖下这一站的印章，石榴里这一瓣亮起，吉祥物庆祝；「撒玛坝这一瓣亮了 · 2 颗籽可以认识，3 颗正在整理」 | 然后呢？ | 生成到访记录；按钮「去认识这一瓣」「先看这一站」 |

**没打上时（四种情况，界面上不出现「失败」）**

| 情况 | 怎么判断 | 游客看到 | 下一步 |
|---|---|---|---|
| 还没到 | 不在打卡范围内 | 还没到 · 距打卡点约 2.3 公里 | 可以先看这一站的内容，但不能答题 |
| 车还在走 | 定位显示速度明显快于步行（每秒 3 米以上） | 请停稳后再打卡（橙色） | 不提供任何「继续」按钮 |
| 信号弱 | 8 秒内没取到位置，或位置误差太大 | 定位信号弱，可以扫现场立牌码 | 打开扫码 |
| 今年已打过 | 本自然年已在这一站打过卡 | 今年已在这一站打过卡 | 可以重看，不重复计分 |

**规则**

- 打卡点只设在高速出口后的访客停车场、游客中心、景区服务点；匝道、主路、路肩、应急车道一律不设，也不出现「拍照点」提示。
- 离线时也能打卡（扫立牌码），记录标「待同步」，有网后自动上传。
- 每站每个自然年计一次分。

**后台对应**：B4（每站的打卡范围、立牌码生成与更换、站点开放状态）。

**记录的数据**：打卡次数、成功率、失败原因分布、行驶中被拦次数（这个数越少说明安全提示越有效）、立牌码使用比例。

### M3 站点内容与答题

**解决什么**：站在现场 3 分钟能看完、能听懂；答题帮游客记住，也让「领礼」有依据。

**链路**

| 步骤 | 游客看到 | 游客心里 | 系统做什么 |
|---|---|---|---|
| 1 站点页 | 深色主题大卡（如「同一片梯田，同一张长桌」）、一行「约 3 分钟 · 完成可得 30 同路分 · 内容已审定」 | 要多久？ | — |
| 2 导览 | 3–4 张卡片，每张不超过 120 字，配插画 | — | 卡片底部写审定单位和日期 |
| 3 听一听 | 一段不超过 3 分钟的普通话音频，有文字稿 | 没信号能听吗？ | 下载过离线包就能听 |
| 4 答一答 | 3 道题，进度三个点 | 会不会很难？ | 题目都出自刚看过的卡片 |
| 5 答对 | 「答对了 +10」 | — | 记分 |
| 6 答错 | 先翻出讲解卡（正确答案和原因），看完按钮变成「我记住了 +3」 | 会扣分吗？ | 不扣分，给 3 分，继续答 |
| 7 记下这一站 | 印章从线描变成填色；本站得分、累计同路分、现在可领第几档 | 接下来干嘛？ | 三个出口：去领礼 / 看这站好物 / 下一站怎么走（只给距离和停车点） |

**四站讲什么**

| 站 | 主题 | 讲的内容 |
|---|---|---|
| 迤萨路口 | 同住一个县，同走一条路 | 县情、五个世居民族、这一路会遇到什么 |
| 马帮侨乡森林公园 | 大家共用一沟水 | 森林—村寨—梯田—水系；护林防火；寨神林的敬重礼仪 |
| 马帮古城 | 出门的人和等的人 | 马帮、侨乡、「江外建筑大观园」；文物保护礼仪 |
| 撒玛坝梯田 | 同一片梯田，同一张长桌 | 梯田与灌水季、开秧门、长街宴、乐作和多声部（分开讲） |

**规则**

- 没打卡也能看导览和听音频，但不能答题、不记分。
- 打卡后 6 小时内可以回到车里或酒店再看完、答完，不用重新定位。
- 题目不能重答刷分，可以随时回看讲解。
- 寨神林、祭祀不做题目素材。

**后台对应**：B2（内容卡、音频与文字稿、题库）、B3（审定）。

**记录的数据**：每站看完率、音频播放完成率、每道题的答对率（答对率特别低的题说明题目或内容有问题，要改）。

### M4 同心石榴（研学）

**解决什么**：把四站里涉及各民族的非遗、节令、手艺内容串起来，让游客愿意多走几站、多了解一点，同时守住政策边界：不做民族图鉴、不排高低、没审定的不讲。

界面名称是「同心石榴」，副标题「交往交流交融 · 研学」。「民族融合」只作内部主题词，不出现在界面上。

**这颗石榴怎么理解**

| 石榴的部分 | 代表 |
|---|---|
| 四瓣 | 四个站 |
| 每瓣里五颗一样大、一样颜色的大籽 | 世居五族：汉、哈尼、彝、傣、瑶 |
| 其余小籽 | 生活在红河的其他各族群众 |
| 一瓣亮起 | 在这一站打过卡 |
| 籽带金边 | 已认识（看完这颗籽的非遗卡并答过题） |
| 虚线籽 | 内容还在整理，暂不讲 |
| 四瓣全亮 | 称号「长廊同心人」，头像边框换成石榴纹 |

**链路**

| 步骤 | 游客看到 | 游客心里 | 系统做什么 |
|---|---|---|---|
| 1 打卡成功 | 石榴里这一瓣由米色变成红色 | 这是什么？ | 按钮「去认识这一瓣」 |
| 2 石榴页 | 一颗石榴，已亮的瓣是红色；提示「每瓣五颗大籽是世居五族，点一颗看看」 | 点哪个？ | 没打卡的瓣也能点开看，但不能答题 |
| 3 点一颗籽 | 这颗籽放大到中间（如「哈尼族 · 在撒玛坝」），同一瓣另外四颗围在四周，用金线连着，每颗下面一行字写一起做的事（如「彝族：一起跳乐作」，没有共同内容的写「一起住在红河」） | — | 这一屏讲的就是「同地共生」 |
| 4 认识这颗籽 | 详情页：非遗卡（名称、级别、一句话、音频）、这颗籽的题、来源；底部固定「和谁一起」 | — | 级别标签必须有出处 |
| 5 答题 | 答对后这颗籽带金边 | — | 这道题算在这一站的 3 道题里，不额外加分 |
| 6 走满 | 四瓣全亮 | — | 称号边框变化 |

**三种特殊的籽**

- 迤萨路口这一瓣是目录：每颗籽放大后写一句县情（如「红河县是全国最大的哈尼族聚居县」），下面列「在哪一站可以认识更多」，点了直接跳过去。
- 整理中的籽：放大后写「我们也住在红河县」「这颗籽的内容正在和县文化馆、民宗局一起整理」，并列出这一瓣里已经可以认识的籽。宁可空着，不编。
- 共同内容（长街宴、马帮与侨乡）不归某一颗籽，放在「和谁一起」里。

**一期有内容的籽**（其余显示整理中）

| 站 | 有内容的籽 |
|---|---|
| 迤萨路口 | 五颗都是目录 |
| 森林公园 | 暂无，待县文化馆、民宗局提供 |
| 马帮古城 | 傣族：傣族传统制陶（省级非遗）；彝族（尼苏）刺绣待文化馆确认 |
| 撒玛坝 | 哈尼族：哈尼多声部（国家级非遗）、开秧门与仰阿娜（节令活动）；彝族：乐作舞（国家级非遗，哈尼族、彝族世代相传） |

**一句红河话**（录音审定后上线）：普通话写在前面、字更大，当地说法只放录音，听一段录音选意思，不计分、不做跟读打分。页面底部写「学一句当地话，是为了更好地交流」。

**后台对应**：B2（每站 × 每个民族的籽内容、状态、和谁一起的关联）、B3（审定）。

**记录的数据**：点开次数最多的籽、「已认识」的籽数、四瓣全亮人数。

### M5 同路分、称号与礼品

**解决什么**：游客最想知道的一件事：「我现在能领什么」。

**三样东西各管什么**

| 东西 | 证明什么 | 怎么来 |
|---|---|---|
| 印章 | 到过 | 打卡 |
| 同路分 | 看懂了 | 答题：对 10 分，错 3 分（先看讲解） |
| 称号 | 走了几站 | 1 站红河来客、2 站红河同路人、3 站红河熟客、4 站长廊同心人 |
| 礼品 | 县里的一份感谢 | 柜台店员扫码发放 |

每站满分 30 分，四站 120 分。同路分不能提现、不能抵现金、不能在商城里抵扣。

**礼品档位**

| 档位 | 条件 | 礼品示例 | 可领柜台 |
|---|---|---|---|
| 一档 · 一站礼 | 走完任意 1 站 | 梯田红米小袋 / 本地茶小样 / 竹编书签（三选一） | 四站都可以 |
| 二档 · 同路礼 | 2 站且 ≥ 40 分 | 红米小礼盒 / 竹编杯垫 | 四站都可以 |
| 三档 · 熟客礼 | 3 站且 ≥ 70 分 | 傣陶小器 / 山货组合 | 森林公园、马帮古城、撒玛坝 |
| 四档 · 同心礼 | 4 站且 ≥ 100 分 | 手艺人署名文创 + 梯田红米 | 马帮古城、撒玛坝 |

礼品实物和数量由县文旅局和合作社商定，后台可以随时调整。

**链路**

| 步骤 | 游客看到 | 游客心里 | 系统做什么 |
|---|---|---|---|
| 1 同路卡 | 「我的」顶部：称号、同路分、四枚印章、「现在可领第二档」 | 我能领什么？ | 实时计算可领档位 |
| 2 选择 | 「现在领是第二档；再走一站可领第三档。今年只能领一次」 | 现在领还是再走？ | 让游客自己选 |
| 3 登记证件（第一次） | 「常用游客」里填姓名和证件号 | 安全吗？为什么要填？ | 只用于「每个证件每年领一次」；服务器只保存加密后的结果，不保存原号 |
| 4 出示领礼码 | 一个二维码（30 秒自动刷新）、下面 6 位数字、「领取人 张** · 证件后四位 2381」「请带证件原件」 | 要带什么？ | 屏幕自动调亮，方便扫 |
| 5 店员扫码 | — | — | 见第 7 节店员端 |
| 6 领到 | 页面立刻变成「已领取 · 第二档 · 梯田红米小礼盒 · 撒玛坝观景台服务点 · 15:20」 | — | 当年礼品区折叠为领取记录；称号和印章还能继续累积 |

**规则**

- 每个证件每个自然年只能领一次，取当时达到的最高一档；领过之后当年不能补差升档。
- 游客不能自己点「已领取」，只能由店员核销。
- 第一档门槛很低，只走了入口站的游客也能在入口游客中心拿到一份小礼。
- 家庭出游每人各自登记、各自领。

**后台对应**：B5（档位规则、礼品、柜台库存）、B7（证件登记去重）。

**记录的数据**：各档领取人数、只走 1–2 站的游客领礼比例、各柜台发放量。

### M6 一路好物

**解决什么**：游客看到的物产能买、能带走；钱和订单落到本地合作社、手艺人手里。

**链路**

| 步骤 | 游客看到 | 游客心里 | 系统做什么 |
|---|---|---|---|
| 1 遇到 | 站点页底部「这一站的物产」2–4 件 | — | 商品必须关联站点 |
| 2 看详情 | 大图、一个价格、规格；「来源档案」页签：生产者、村寨、采收时间、配送方式、在哪一站遇到 | 是不是正宗的？贵不贵？ | 只有一个价格，不做划线价、不做倒计时 |
| 3 先收藏 | 入口站（迤萨路口）只能「加心愿单」 | 刚下高速不想买 | 不在停车场催付款 |
| 4 下单 | 选寄回家 / 柜台自提 / 营地自提，微信支付 | 带不走怎么办？ | 统一由运营主体收款 |
| 5 合作社接单 | （合作社手机上）新订单：「买家在撒玛坝观景台看完梯田一站后下单」 | — | 见第 7 节合作社端 |
| 6 发货 | 订单页显示「已发货 · 快递单号」 | 什么时候到？ | 合作社填单号后通知游客 |
| 7 收货评价 | 评价入口 | — | 评价先机器审核、再人工复核，通过后公开 |
| 8 再买 | 「再买一次」 | — | 旅居客常用 |

**规则**

- 只卖本地农特产和文创，没有来源档案的商品不能上架。
- 森林公园相关商品不卖明火类商品，营地自提商品页常驻防火提示。
- 商城结算页不出现任何积分字样。

**后台对应**：B6（合作社、商品、来源档案、订单、售后、结算）。

**记录的数据**：心愿单数、下单数和金额、按「在哪一站之后下单」统计的带动订单、复购率、退款率。

### M7 问驮驮

**解决什么**：游客习惯「问一问」，但关于民族、宗教、文物的问题绝不能乱答。

吉祥物「驮驮」是一匹驮货的小马，挂着铃铛、背着竹背篓（红米、茶叶），不穿民族服装，谁都能代入。底部导航中间那个圆形按钮就是它。

**链路**

| 步骤 | 游客看到 | 系统做什么 |
|---|---|---|
| 1 打开 | 常见问题按钮：哪里停车、厕所在哪、礼品怎么领、灌水季是什么时候 | — |
| 2 提问 | 输入问题 | 在已审定的问答库里查找 |
| 3 找到了 | 答案 + 下方一行来源（如「来源：红河县文化馆 · 已审定」） | 记录 |
| 4 没找到 | 「这个问题还没有审定过的说法，可以问柜台工作人员」+ 柜台电话 | 把问题记进「未答问题」 |
| 5 敏感问题 | 直接给标准回复，不查找 | 记录 |

一期的问驮驮是「查问答库」，不是会自己生成答案的人工智能，所以不需要做大模型备案。二期如果要接大模型改写答案，要先完成生成式人工智能服务备案和安全评估，并且仍然只复述审定内容。

**后台对应**：B7（问答库、未答问题、敏感词）。

**记录的数据**：提问数、答上率、未答问题清单。

### M8 我的

**内容**：同路卡（称号、分数、印章、可领档位）、同路册（四页四枚印章）、我的礼品、我的订单、常用游客（证件登记、同行人）、离线包、电子发票、现场礼仪（拍摄、宴席、乐作、寨神林、文物、防火六条）、意见反馈、服务 / 救援 / 投诉电话、关于与审定单位、设置。

只有被后台绑定的店员、合作社才会看到「店员工作台」「商家工作台」入口。

**规则**：「关于」页列出出品单位、指导单位、内容审定单位。如果和州级「石榴结籽心连心·红河儿女心向党」品牌联名，标识只放在这里，不进首页和现场页。

## 7. 店员端与合作社端

### 7.1 店员端：柜台核销

**谁能用**：后台按「微信身份 + 柜台」登记的店员。每次进入都校验身份，离职后台一停用就进不来。

**链路**

| 步骤 | 店员看到 | 店员做什么 |
|---|---|---|
| 1 进入 | 柜台名、今日已发放、各档库存，大按钮「扫领礼码」 | 点扫码 |
| 2 扫码 | 结果卡（见下表） | 扫不出时手输 6 位数字 |
| 3 核对 | 「张** · 证件后四位 2381 · 走过 2 站 · 64 分」 | 核对游客证件原件的姓名和后四位，勾选「已核对」 |
| 4 选礼品 | 本柜台这一档可发的礼品和余量 | 按游客意愿选一件 |
| 5 确认发放 | 「已发放」 | 游客手机同时变成「已领取」，库存减一 |

**扫码后可能出现的八种结果**

| 结果 | 店员看到 | 店员怎么做 |
|---|---|---|
| 可发放 | 档位、领取人、可发礼品 | 核对证件 → 选礼品 → 确认 |
| 已发放 | 发放时间、店员 | 下一位；10 分钟内可申请主管撤销 |
| 今年已领 | 该证件今年在哪领过哪一档 | 向游客解释每证每年一次 |
| 码已过期 | 请游客刷新后再扫 | 重新扫 |
| 本柜台无此档 | 第四档需在马帮古城或撒玛坝领取 | 告知游客可领柜台 |
| 库存不足 | 本档礼品已发完 | 换同档其他礼品，或告知其他柜台 |
| 未登记证件 | 游客尚未登记证件 | 请游客在「我的 → 常用游客」登记后刷新 |
| 网络异常 | 需要联网才能核销 | 稍后重试；不提供离线发放，避免重复发 |

### 7.2 合作社端：订单与发货

**谁能用**：后台登记的合作社、手艺人账号。

**链路**：收到新订单通知 → 看订单（商品、数量、收货方式、买家在哪一站之后下单）→ 备货发货 → 填快递单号（自提订单点「已备好」）→ 游客收货 → 每月在「对账」里看本月订单和应结金额。

不习惯用手机的合作社，由运营人员在后台代为操作，订单通过电话或短信通知。

## 8. 运营后台：八个模块

运营后台在电脑浏览器上使用。原则：每一个游客能看到的东西，后台都有地方管；每一个关键动作，后台都有记录。

### B1 工作台与权限

**角色**

| 角色 | 谁 | 能做什么 |
|---|---|---|
| 系统管理员 | 运营主体技术负责人 | 账号、角色、系统设置 |
| 运营人员 | 运营主体 | 录入内容、发公告、管礼品商品订单、处理留言 |
| 审定员 | 县文化馆、民宗局、文旅局、文物部门各指定人员 | 只能审定分给自己的内容，写意见，通过或退回；可以申请下线 |
| 柜台主管 | 各景区服务点负责人 | 看本柜台库存和发放记录，审批撤销，提补货 |
| 店员 | 柜台工作人员 | 不进后台，只用小程序店员端 |
| 合作社 | 入驻的合作社、手艺人 | 不进后台（一期），只用小程序合作社端 |
| 领导查看 | 县领导、局领导 | 只看数据看板和月度简报 |

**工作台首页**：待我处理（待审内容、待处理留言、库存预警、未答问题、退款申请）、今日概况（打卡人数、领礼数、订单数）。

**操作日志**：谁、什么时间、改了什么，全部留痕，不能删除。

| 管什么 | 主要字段 | 说明 |

| 站点 | 名称、主题、停车点说明、开放状态、关联物产 | 停车点说明写「游客真正站着的地方」 |

| 首页大图 | 图片、跳转页、上下线时间 | 只放季节、正式活动、开放提醒 |

### B3 审定中心

**审定流程**

| 状态 | 谁操作 | 下一步 |
|---|---|---|
| 草稿 | 运营人员 | 提交审定 |
| 待文化馆审 | 县文化馆 | 通过 / 退回（必须写意见） |
| 待民宗局审 | 县民宗局 | 通过 / 退回 |
| 待文物部门审（仅古城相关内容） | 文物主管部门 | 通过 / 退回 |
| 待文旅局发布 | 县文旅局 | 发布 / 退回 |
| 已上线 | — | 任何审定单位都可以申请下线；运营可以紧急下线 |
| 已下线 | — | 修改后重新从草稿开始 |

**审定员看到的页面**：左边是内容在手机上的样子，右边是审查要点（是否落到共同性、有没有罗列差异或猎奇化、族语是否以普通话为主、级别标签是否有出处），下面是历次修改对比和意见记录。

**一键下线**：内容卡下线时，关联的题目、石榴籽状态同步下线；游客已经得到的分数保留，看过的卡片显示「该内容正在更新」。

**线上展示**：每张内容卡底部显示「内容经县民宗局、文旅局、文化馆审定 · 2026 年 X 月」。

## 10. 分阶段建设与验收

### 一期：跑通主线

**做**：M1–M8 全部（问驮驮为问答库查询，一句红河话等录音审定后再开）、店员端、合作社端、运营后台 B1–B8。

**不做**：持续定位、导航、AR、生成式人工智能讲解、族语文字内容、支线、节庆页、外语正文。

**验收标准**（上线前逐条检查）

1. 四站都能打卡：定位和扫立牌码两种方式都能成功；行驶中不能打卡。
2. 四站内容和题目全部经过审定，审定记录完整。
3. 领礼全流程：登记证件 → 出示领礼码 → 店员扫码 → 发放 → 游客端显示已领取；同一证件第二次领被拦住。
4. 下单全流程：下单 → 支付 → 合作社收到通知 → 填单号 → 游客收到发货通知。
5. 一键下线：下线一张内容卡，关联题目同步下线，游客分数保留。
6. 数据看板能看到当天的打卡、领礼、订单数据。
7. 没信号时：下载过离线包的站点能看、能听、能打卡（扫码），有网后记录自动同步。

### 二期：内容做深、渠道做广

撒玛坝「左右滑动看四层」分层图（森林、村寨、梯田、水系）；研学与团队模式（班级码、团队码、研学证书）；官方环线支线（甲寅、宝华、乐育）；营地常备清单、帮扶单位团购、微信支付分账；一句红河话；AI 讲解员（备案后）。

### 三期：体验做宽

马帮过街动画（古城站）、真正的 AR 体验（可选）、英文导览、越南语和老挝语（各自单独审定后）。

## 12. 风险与应对

| 风险 | 应对 |
|---|---|
| 游客在匝道停车拍照、开车时操作 | 打卡点只设在访客点；必须先选「已停稳 / 乘客」；车还在走时不给打卡；匝道处不出现任何拍照提示 |
| 山区信号弱 | 离线包、扫立牌码打卡、记录待同步；只有领礼核销必须联网 |
| 民俗、民族表述出错 | 四方审定、审定记录展示、一键下线、游客纠错入口 |
| 「交往交流交融」被理解成同化，或反过来只讲差异 | 对外统一用「交往交流交融」；每站落到共同性，同时尊重差异；民宗局专项审查 |
| 礼品被重复领取 | 证件登记去重、柜台核对证件原件、每证每年一次、30 秒刷新的领礼码、只有登记店员能核销、核销必须联网 |
| 合作社发货慢、质量问题 | 超时提醒、售后记录、退款率进入看板；连续出问题的商品下架 |
| 森林火灾、山体滑塌 | 防火公告置顶；营地商品页常驻提示；不卖明火类商品；立牌避开滑塌点 |
| 引导游客去未建成或受保护的地方 | 望江亭建成前只讲故事；开放状态由后台控制；文物礼仪就近提示 |
| 数据过时 | 县情数据集中管理，每年更新一次 |
| 使用未授权的素材 | 素材库标注授权，未授权的不能选用 |
