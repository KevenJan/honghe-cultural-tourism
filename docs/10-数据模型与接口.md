# 红河同路 · 数据模型与接口

> 版本 v1.0 · 2026 年 10 月
> 读者：后端、前端、测试。上游：[`09-功能交互规格/`](09-功能交互规格/README.md)（页面、交互、规则口径）。字段名用英文蛇形；类型按 PostgreSQL 写，换 MySQL 时对应替换。
> 规则判断（打卡、计分、档位、令牌）的精确口径以 09 号 [`04-规则与计算口径.md`](09-功能交互规格/04-规则与计算口径.md) 为准，本文件只定义数据和接口。

## 1. 技术约定

| 项 | 约定 |
|---|---|
| 主键 | `id bigint`（雪花或自增）；对外暴露的 ID 用 `public_id`（短随机串），不暴露自增 ID |
| 时间 | `timestamptz`，存 UTC；接口输出 ISO 8601 带 `+08:00` |
| 金额 | `integer`，单位分 |
| 软删除 | 业务表不物理删除；`status` 字段表达下线 / 停用 / 作废 |
| 版本 | 内容类对象有 `version`；线上读 `published_version`，编辑写新版本 |
| 年度 | 涉及年度的表带 `year smallint`，按北京时间计算 |
| 审计 | 所有后台写操作写 `audit_log`（只追加） |
| 敏感字段 | 证件号不落库；姓名只存「姓 + *」；收货地址、手机号字段级加密（AES-GCM，密钥在 KMS），发货后 30 天在合作社端脱敏 |

## 3. 状态机

### 3.1 内容审定

```
draft ──submit──▶ reviewing(culture_center) ──pass──▶ reviewing(ethnic_affairs)
   ▲                     │reject                          │pass
   │                     ▼                                ▼
   └──────────────── draft(带意见) ◀──reject── reviewing(relics, 仅 needs_relics)
                                                          │pass
                                                          ▼
                                            reviewing(tourism_bureau) ──publish──▶ published
published ──request_offline / emergency_offline──▶ offline ──edit──▶ draft
published ──edit──▶ 新版本 draft（线上仍为旧 published_version）
```

### 3.2 订单

| 当前 | 事件 | 下一状态 | 副作用 |
|---|---|---|---|
| pending_pay | 支付回调 | to_ship / to_prepare | 扣减锁定库存；通知合作社 N-S01 |
| pending_pay | 15 分钟 / 用户取消 | cancelled | 释放库存 |
| to_ship | 合作社填单号 | shipped | auto_confirm_at = now + 10d；N-U01 |
| to_prepare | 合作社「已备好」 | ready | 生成 pickup_code；N-U02 |
| ready | 柜台核销 | completed | — |
| shipped | 用户确认 / 到期 | completed | — |
| to_ship / to_prepare | 未发货退款 | cancelled(refunded) | 退款；释放库存 |
| shipped / completed(≤7d) | 售后提交 | （订单状态不变，`aftersale` 独立流转） | — |

### 3.3 售后

```
submitted ─(unshipped_refund)─▶ approved ─▶ refunding ─▶ done
submitted ─▶ wait_merchant(24h) ─respond/timeout─▶ wait_admin ─approve─▶ refunding / reshipping ─▶ done
                                                           └─reject─▶ closed（可再申请 1 次）
refunding ─微信退款失败─▶ refund_error（人工）
```

### 3.4 领礼令牌与发放

```
issued(30s) ─新令牌─▶ replaced
issued ─到期─▶ expired
issued ─店员 check─▶ scanned(lock 60s) ─confirm─▶ redeemed
                         └─lock 到期─▶ issued（若未过期）/ expired
redemption.done ─revoke approved─▶ revoked（库存 +1，删除 redemption_year_lock）
```

### 3.5 对账

`pending ─merchant confirm / 7 天─▶ confirmed ─admin mark paid─▶ settled`；`pending ─dispute─▶ disputed ─admin regenerate(version+1)─▶ pending`。

### 3.6 离线同步记录

客户端：`queued ─提交─▶ synced / rejected(reason)`；服务端按 `request_id` 幂等，同一 `request_id` 返回同一结果。

## 4. 小程序接口 `/api/v1`

**通用**：HTTPS；请求头 `Authorization: Bearer {session_token}`（`wx.login` 换取，30 天）；`X-Request-Id`（写操作必带，UUID，用于幂等）；`X-App-Version`。返回 `{code, message, data}`；分页 `?cursor=&limit=`，返回 `next_cursor`。错误码见 09 号 [`05-通知文案与埋点.md`](09-功能交互规格/05-通知文案与埋点.md) 第 2 节。

## 7. 安全与隐私

| 项 | 做法 |
|---|---|
| 证件号 | 只在 `POST /travelers` 请求中出现；服务端规范化后 HMAC（pepper 在 KMS），存哈希 + 后四位；请求日志对该字段打码；不写入任何日志、埋点、备份 |
| 坐标 | 只用于本次判定，不入库、不进日志；入库只存距离档、精度档 |
| 收货信息 | 字段级加密；合作社端发货后 30 天脱敏；订单按法定期限保留（电子商务法，3 年） |
| 令牌 | 二维码内容为随机 128 位；库内存 `token_hash`；6 位码限速 |
| 后台 | 密码 argon2id；短信二次验证；5 次失败锁定；30 分钟超时；IP 白名单（可选） |
| 审计 | `audit_log`、`violation` 表：应用数据库账号只有 INSERT/SELECT 权限 |
| 接口防刷 | 按 user / IP 限流；打卡、出码、提问、反馈单独限流 |
| 内容安全 | 用户输入（反馈、评价、问驮驮）调用微信内容安全接口 `msgSecCheck` / `mediaCheckAsync` + 本地敏感词 |
| 等级保护 | 建议按网络安全等级保护二级备案 |
