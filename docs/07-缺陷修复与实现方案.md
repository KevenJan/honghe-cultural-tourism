# 红河同路 · 缺陷修复与实现方案

> 版本 v2.2 · 对 01–06 号文件和设计图做一次通盘检查，修复明显缺陷，把实现上走不通或代价过高的地方改成能落地的做法
> 本文件里的修复已同步改进对应文件；冲突时以本文件为准

---

## 0. 结论

一共 28 处，分三类：

| 类别 | 数量 | 说明 |
|---|---|---|
| A. 表述与合规 | 5 | 有一处和本项目自己的政策审查结论冲突，必须改 |
| B. 实现困难 | 15 | 微信小程序做不到或代价太高，改成能落地的做法 |
| C. 设计缺陷 | 8 | 规则自相矛盾、文案和实际状态不符、效果图文字错误 |

改动最大的三处：

1. 界面上不再出现「民族融合」四个字，研学模块改名 **「同心石榴」**。
2. 领礼的实名改成「**证件号去重 + 柜台核验证件**」。微信小程序拿不到用户的身份证号，原设计的「微信实名授权」做不了。
3. 汇报和评审用的关键页面改用 **HTML 重绘**（`presentation/`），文字准确；AI 效果图只作氛围参考。

## B. 实现困难

| # | 原设计 | 问题 | 改为 |
|---|---|---|---|
| B1 | 领礼前「微信实名授权」，柜台核对证件后四位 | 普通小程序拿不到用户的证件号；微信的实名核身能力只开放给政务、金融等特定类目 | **一期**：游客在「常用游客」里填写姓名和证件号，服务端只存证件号的加盐哈希，用于「每证每年一次」去重；柜台店员核对**证件原件**的姓名和后四位后再发放。**二期**：如果运营主体有资质，可接入第三方身份二要素核验。界面文字「未实名」改为「未登记证件」 |
| B2 | 底部 5 个标签、中间一个凸起的吉祥物按钮 | 原生 `tabBar` 不支持凸起按钮，也不支持 SVG 图标 | 用**自定义 tabBar**（`custom-tab-bar`）。图标用 PNG：`assets/icons/tab/png/`，81×81，每张小于 3KB |
| B3 | 可交互石榴是 SVG，靠切换 class 改变状态 | 小程序 `<image>` 能显示 SVG，但不能操作内部节点，也不能单独点击某颗籽 | 新增 `assets/illustrations/pomegranate/pomegranate-layout.json`，里面是每颗籽的坐标、尺寸和旋转角度。前端用绝对定位的 `view` 画 20 颗可点的命名籽，64 颗装饰小籽合成一张底图。也可以用 `canvas type="2d"` 绘制、按坐标判断点击 |
| B4 | 首页「在站点附近时浮出『到了』提醒」 | 没有持续定位就无法感知用户在不在附近 | 只在两种情况下出现：从现场**桩码**扫码进入（小程序码带站点参数）；或用户当天已主动点过一次「到达打卡」。首页不主动取位置 |
| B5 | 单次定位判断「是否仍在行驶」 | `wx.getLocation` 返回的 `speed` 在部分机型不可信，可能是 0 或 -1 | `speed` 大于 3 米/秒（约 11 公里/时）时提示「请停稳」；取不到 `speed` 时只依赖「我已停稳 / 我是乘客」的勾选。速度判断只作辅助，不作为唯一的安全依据 |
| B6 | 定位接口直接用 | `wx.getLocation` 要在小程序后台申请接口权限，类目要匹配；还要在 `app.json` 里声明，并配置隐私保护指引 | 上线清单加入：申请 `getLocation` 接口权限（旅游类目）；在 `requiredPrivateInfos` 里声明；隐私保护指引写明「仅在你点击『我到了』时获取一次位置，用于确认到达」 |
| B7 | 「离线可用」 | 小程序首次打开、登录都要联网；本地缓存（`setStorage`）上限 10MB | 离线只覆盖**下载过离线包的站点**：音频和图片存在本地文件目录（`wx.env.USER_DATA_PATH`），打卡和答题记录存在本地缓存、标「待同步」。迤萨路口站和首页提示「进山前先下载离线包」。领礼核销必须联网 |
| B8 | 动态领礼码 30 秒刷新 | 需要服务端签名，游客离线时无法生成 | 服务端签发 30 秒有效的一次性令牌，二维码里只有令牌；店员端扫码（`wx.scanCode`）后由服务端校验并核销。游客端和店员端都必须联网，离线时领礼码页显示「请连上网络再出示」 |
| B9 | 店员模式 | 需要防止普通游客冒用 | 店员由后台按「微信身份 + 柜台」白名单绑定；店员工作台每次进入都校验身份；核销记录 10 分钟内可由主管撤销 |
| B10 | 一路好物直接卖农产品 | 小程序卖预包装食品需要对应的服务类目和《食品经营许可证》；收款需要微信支付商户号；把钱直接分给合作社需要「分账」能力 | 一期由**一个运营主体**统一开店、统一收款，按订单来源和合作社线下结算；二期开通微信支付分账。上线前由运营主体准备类目资质 |
| B11 | 撒玛坝 AR 分层（二期） | 小程序 AR（VisionKit / xr-frame）开发量大，户外识别率不稳定，机型兼容差 | 二期先做**「左右滑动的四层分层图」**：同一视角的森林、村寨、梯田、水系四层插画，手指滑动逐层叠加，所有机型都能用。真 AR 降为三期可选项 |
| B12 | 素材总量约 20MB | 小程序主包不超过 2MB，总包不超过 20MB | 主包只放 tab 和界面小图标；吉祥物、插画全部放 CDN（webp）；四站各做一个分包，按需加载 |
| B13 | 石榴放大动画 | 低端机上缩放加模糊会卡顿 | 只用 `transform: scale` 和透明度，不用实时模糊；背景改为一层半透明深色遮罩。系统开启减弱动态效果时改为淡入 |
| B14 | 一句红河话的录音 | 录音的授权、发音人署名、审定都要有记录，否则不能上线 | 内容后台为每条录音建档：发音人（经同意署名）、授权书编号、审定单位和日期；没有授权书的录音不能选入内容卡 |
| B15 | 30 秒刷新的二维码在柜台强光下难扫 | 户外强光、屏幕反光 | 领礼码页自动把亮度调到最高（`wx.setScreenBrightness`），离开时恢复；同时在码下方显示 6 位数字，扫不出来时店员可以手输 |

## C. 设计缺陷

| # | 问题 | 修复 |
|---|---|---|
| C1 | 打卡成功文案「5 颗籽等你认识」，但撒玛坝这一瓣一期只有 2 颗籽有审定内容 | 按实际数量写：「撒玛坝这一瓣亮了 · **2 颗籽可以认识，3 颗正在整理**」 |
| C2 | 籽的「已认识」金边依赖「一句红河话」，但一期这个页签是隐藏的，金边永远拿不到 | 「已认识」改为：**看完这颗籽的非遗卡，并答过这颗籽的题**。听方言只是额外内容，不影响状态 |
| C3 | 迤萨路口一瓣的五颗籽内容完全一样（都是县情），点开五次看到同一张卡 | 迤萨路口的籽改作「**索引**」：每颗籽放大后写一句县情（如「红河县是全国最大的哈尼族聚居县」），下面列「在哪一站可以认识更多」并直接跳转。路口这一瓣成为全模块的目录 |
| C4 | 首页顶栏在未登录时也显示「64 同路分」 | 未登录显示「登录记分」，登录后显示分数 |
| C5 | 打卡页「我已停稳」「我是乘客」在一张图里画成了两个勾选框，可以同时选 | 改为二选一的胶囊，必须选一个才能点「我到了」 |
| C6 | AI 效果图里有错字和乱码：四站卡角标、答题选项、结果页「本科」、服务地图标题、店员礼品、「在撒玛嘛」等 | 汇报和评审改用 `presentation/` 里的 **HTML 重绘页面**，文字以文档为准；AI 效果图只作风格参考，并保留 04、06 号文件里的勘误表 |
| C7 | 效果图里的石榴总是四瓣全亮，看不出打卡进度 | HTML 汇报里的石榴是**可交互**的：按打卡进度点亮，点击籽会放大 |
| C8 | 「整理中」的籽点开后只有一句话，容易被理解为内容缺失 | 整理中的籽放大后显示两行：「我们也住在红河县」+「这颗籽的内容正在和县文化馆、民宗局一起整理」，并给出这一瓣里已有内容的籽，可以直接点 |
