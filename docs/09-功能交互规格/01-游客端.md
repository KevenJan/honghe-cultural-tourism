> 写法见 [README](README.md) 第 1 节。计分、档位、时间窗等规则只在这里引用，精确口径以 [`04-规则与计算口径.md`](04-规则与计算口径.md) 为准。

## M1 入口与首页

### F1-1 首页（P01）

**闭环位置**：游客体验闭环 L1 的入口。起点是游客打开小程序，终点是游客进入某一站（P03）或直接去打卡（P04）。

**入口**：小程序默认首页；公众号菜单；宣传物料码（`ch` 参数记录渠道）；分享。

**页面元素（从上到下）**

| # | 元素 | 内容来源 | 说明 |
|---|---|---|---|
| 1 | 顶栏 | 固定 | 左：文字标「红河同路」+ 副标题「各族同路走，好物一路带」；右：未登录「登录记分」胶囊 / 已登录「{年度同路分} 分」胶囊；「中 / EN」切换 |
| 2 | 首页大图（轮播，最多 3 张） | B2 首页大图 | 每张：图片、标题、一行说明、按钮文字、跳转页；按上下线时间自动切换 |
| 3 | 八格入口 | 固定 | 到达打卡、四站、同心石榴、问驮驮、领礼、一路好物、服务地图、研学团队 |
| 4 | 公告条 | B4 公告 | 只显示 1 条：有置顶公告显示置顶，否则显示最新一条；没有公告就不显示这一行 |
| 5 | 今日开放 | B4 开放状态 | 四个站名 + 状态点（绿 开放 / 黄 部分开放 / 灰 暂停）；全部开放时这一行收起为「四站今日都开放」 |
| 6 | 四站长廊 | B2 站点 | 横向滑动四张小卡：站点插画、站名、主题字（路、水、田、街）；下面一行灰字「可顺可逆，从哪站开始都行」 |
| 7 | 这季在红河 | B2 首页大图同源 | 2–4 张季节卡（例：灌水季、开秧门）；没有配置就不显示 |
| 8 | 为您推荐（好物） | B6 商品，按「首页推荐」排序 | 4 件，双列；入口站附近不做「立即购买」，只有「看看」 |

**交互**

| 用户操作 | 界面反馈 | 系统 |
|---|---|---|
| 点「登录记分」 | 弹登录层（README 3.1） | — |
| 点「{n} 分」 | 进 P23 称号与礼品 | — |
| 点大图 | 按配置跳转：站点页 / 同心石榴 / 商品 / 公告详情 / 文章（富文本） | `ev_banner_click` |
| 点「到达打卡」格子 | 有「今天正在进行的站」（今天打过卡或扫过立牌码的站）→ 直接进该站 P04；否则弹底部选择层「你现在在哪一站？」四个站名按钮 + 一行「不确定？用服务地图看看」 | 不取位置 |
| 点「四站」 | 切到四站标签 P02 | — |
| 点「领礼」 | 已登录进 P23；未登录先登录 | — |
| 点「研学团队」 | Toast「研学团队二期开放」 | — |
| 点公告条 | 展开公告详情半屏层；置顶公告没有关闭按钮，普通公告有「知道了」 | 普通公告点「知道了」后本地记住，24 小时内不再显示同一条 |
| 点「今日开放」某站 | 进该站 P03 | — |
| 下拉 | 刷新公告、开放状态、大图 | — |

**状态**

| 状态 | 表现 |
|---|---|
| 首次加载 | 骨架屏；八格入口是本地固定内容，立即显示 |
| 没网 | 大图、推荐用上次缓存；公告条显示缓存内容并标「离线」 |
| 大字模式 | 只保留：到达打卡（大按钮）、四站、领礼、服务电话、公告条 |

**规则**

- 首页不放商业广告、外部链接、弹窗广告。
- 首页不主动取位置。「到达打卡」格子判断「今天正在进行的站」只看本地记录。

**验收要点**

1. 未登录时右上角是「登录记分」，不是分数。
2. 后台设置置顶公告后，首页公告条显示它且没有关闭按钮。
3. 某站设为「暂停」后，首页今日开放该站为灰色，点进去站点页顶部显示原因。

### F1-2 四站（P02）

**闭环位置**：L1。起点是游客想知道「先去哪」，终点是进入某一站。

**页面元素**：顶栏标题「四站」，左侧文字按钮「服务地图」。四张大卡，每张：站点插画背景、主题角标（同一条路 / 同一沟水 / 同一条街 / 同一片田）、站名、主题句、「停车：{停车点}」、本人状态标签、「看这一站」按钮。

**本人状态标签**（登录后显示）

| 状态 | 标签 |
|---|---|
| 今年没去过 | 不显示 |
| 打过卡、题没答完 | 「还差 {n} 题」（黄） |
| 完成 | 「已记下 · {本站得分} 分」（绿） |
| 站点暂停 | 「今日暂停」（灰），覆盖上面的标签 |

**交互**：点卡片或按钮进 P03；点「服务地图」进 P08（不带站点参数时显示全县）。

**验收**：四张卡没有编号、没有锁、没有「下一站」箭头。

---

### F1-3 服务地图（P08）

**闭环位置**：辅助。起点是游客要找停车场、厕所等，终点是交给微信地图导航。

**页面元素**：顶部分类胶囊（全部 / 停车场 / 厕所 / 服务柜台 / 医疗点 / 充电桩）；地图（`map` 组件，显示服务点标记，不画路线）；底部卡片：选中点的名称、类型、开放时间、距离（仅在用户本次打卡取过位置时显示距离，否则不显示）、「用微信地图打开」按钮；卡片下小字「只标服务点，不画路线」。

**交互**

| 操作 | 反馈 | 系统 |
|---|---|---|
| 点分类 | 地图只显示该类标记 | — |
| 点标记 | 底部卡片切换到该点 | — |
| 点「用微信地图打开」 | 调 `wx.openLocation`，由微信地图负责导航 | `ev_map_navigate` |
| 带 `site` 参数进入 | 地图缩放到该站服务点范围 | — |

**规则**：服务点数据来自 B4；没有坐标的点不显示。不在地图上标「拍照点」「观景点」。

### F1-4 中英切换

一期英文只覆盖：站名、站点主题句、安全提示（停稳、防火、文物）、礼品规则、服务电话页。切到 EN 后，未翻译的正文仍显示中文，顶部提示「English covers safety and gift rules only in this version.」。语言选择本地保存。

## M2 到达打卡

### F2-1 打卡页（P04）

**闭环位置**：L1 的第一步。起点是游客停好车点开打卡页，终点是打卡成功（进 P05）或被告知下一步该做什么（还没到 / 请停稳 / 扫码 / 今年已打过）。

**入口与参数**

| 入口 | 参数 |
|---|---|
| 首页「到达打卡」格子 → 选站 | `site` |
| 站点页底部「到达打卡」按钮 | `site` |
| 现场立牌码 | `from=board&board={立牌码ID}`，站点由立牌码反查 |

**页面元素**

| # | 元素 | 说明 |
|---|---|---|
| 1 | 顶部插画 | 这一站的插画，站名压在图上 |
| 2 | 「你现在应该在」卡片 | 停车点名称（例「观景台停车场」）+ 绿色标签「访客点」；下面一行灰字开放时间 |
| 3 | 站点状态条（条件） | 部分开放 / 暂停时出现，写原因。暂停时下面的按钮全部置灰 |
| 4 | 防火提示（条件） | 森林公园站常驻橙色条「森林防火期 · 请勿携带火种」 |
| 5 | 二选一胶囊 | 「我已停稳」「我是乘客」，默认都不选 |
| 6 | 大圆按钮「我到了」 | 未选二选一时置灰 |
| 7 | 按钮下小字 | 「只在点击时取一次位置」 |
| 8 | 文字按钮 | 「定位不准？扫现场立牌码」 |

**交互**

| 用户操作 | 界面反馈 | 系统 |
|---|---|---|
| 未选胶囊就点「我到了」 | 按钮轻微左右晃动，胶囊上方出现一行橙字「先选一个：我已停稳，或我是乘客」 | 不取位置 |
| 选「我已停稳」或「我是乘客」 | 胶囊变绿带勾，另一个取消；「我到了」按钮变亮 | 记录选择，随打卡提交 |
| 点「我到了」（未登录） | 先登录（README 3.1），登录完自动继续 | — |
| 点「我到了」（第一次） | 隐私弹窗（README 3.2）→ 系统位置授权 | — |
| 点「我到了」 | 全屏半透明遮罩，按钮外一圈圈扩散，文字「正在确认位置…」，下面小字「超过 8 秒会提示定位信号弱」 | `wx.getLocation` 一次，见 F2-2 |
| 从立牌码进来 | 「我到了」按钮文字变成「确认到达」；小字变成「已扫现场立牌码，不需要取位置」 | 见 F2-3 |
| 点「扫现场立牌码」 | 调起扫码（`wx.scanCode`，只允许小程序码） | 见 F2-3 |

**验收**：二选一必须选；同一时间只能选一个；页面里任何地方都不出现「拍照点」。

### F2-2 定位比对

**规则**（精确口径见 04 号第 2 节）

1. 前端拿到 `latitude, longitude, accuracy, speed` 后提交 `POST /checkins`，带上二选一选择、客户端时间。
2. 服务端按顺序判断，命中一条就返回：

| 顺序 | 条件 | 结果码 | 前端去向 |
|---|---|---|---|
| 1 | 站点状态「暂停」 | `SITE_CLOSED` | 留在 P04，状态条已说明，Toast「这一站今天暂停开放」 |
| 2 | `speed > 速度阈值`（默认 3 米/秒，B4 可配） | `MOVING` | 留在 P04，见 F2-4「车还在走」 |
| 3 | `accuracy > 精度阈值`（默认 200 米） | `WEAK_SIGNAL` | 见 F2-4「信号弱」 |
| 4 | 不在打卡范围（距中心点 > 半径） | `NOT_ARRIVED` | 见 F2-4「还没到」 |
| 5 | 本自然年在这一站已有完成记录 | `ALREADY_DONE` | 见 F2-4「今年已打过」 |
| 6 | 本自然年已打卡但题没答完 | `REOPENED` | 进 P05，答题时间窗重新计 6 小时，不重复盖章动画（改为「欢迎回来」） |
| 7 | 以上都不是 | `OK` | 进 P05 |

3. 8 秒内取不到位置：前端直接显示「信号弱」，不调接口。
4. 取到的坐标只用于这一次判断，服务端只保存「是否在范围内、距离取整到 100 米、精度档位」，不保存原始坐标。

### F2-3 扫立牌码打卡

1. 小程序码 `scene=b{立牌码ID}`。服务端查立牌码：是否存在、是否作废、属于哪一站。
2. 作废码：进 P03，顶部提示「这个码已经更换，请扫现场的新码」。
3. 有效码：进 P04 的扫码状态；用户仍需选「我已停稳 / 我是乘客」，点「确认到达」后提交 `POST /checkins`，`method=board`，不带坐标，不做速度判断。
4. 扫的是别的站的码（从 A 站打卡页扫到 B 站码）：Toast「这是{B 站}的码」，页面切换到 B 站。
5. 扫的不是本小程序的码：Toast「请扫现场立牌上的二维码」。
6. 离线扫码：见 F2-6。

### F2-4 没打上时

界面上不出现「失败」二字。四种情况各占一张状态卡，替换「我到了」按钮区域：

| 情况 | 图标与颜色 | 标题 | 说明 | 按钮 |
|---|---|---|---|---|
| 还没到 | 定位图标，青色 | 还没到 | 距打卡点约 {x} 公里（取整到 0.1 公里；超过 50 公里写「距打卡点还很远」） | 「先看这一站的内容」→ P03；「再试一次」 |
| 车还在走 | 停车图标，橙色 | 请停稳后再打卡 | 车辆行驶中不能打卡，停好车再点 | **无任何按钮**。10 秒后状态卡自动收起，回到二选一 |
| 信号弱 | 扫码图标，青色 | 定位信号弱 | 可以扫现场立牌码完成打卡 | 「扫立牌码」；「再试一次」 |
| 今年已打过 | 勾图标，青色 | 今年已在这一站打过卡 | 可以重看，不重复计分 | 「回到这一站」→ P03；「去认识这一瓣」→ P09 |

**验收**：模拟 speed=5 时只出现橙色卡且没有按钮；8 秒超时出现「信号弱」。

### F2-5 打卡成功（P05）

**闭环位置**：L1 第一步的终点，同时是 M3、M4 的起点。

**页面元素**

| # | 元素 | 说明 |
|---|---|---|
| 1 | 同路册页 | 「同路册 · 第 {n} 页」，日期，印章从上方落下盖在纸上（0.45 秒，只播一次） |
| 2 | 小石榴 + 吉祥物庆祝 | 这一瓣由米色变红（0.6 秒） |
| 3 | 主文案 | 「{站简称}这一瓣亮了」 |
| 4 | 副文案 | 「{a} 颗籽可以认识，{b} 颗正在整理」；迤萨路口写「这一瓣是整颗石榴的目录」 |
| 5 | 称号变化（条件） | 称号升级时多一行：「称号升级为「{称号}」」 |
| 6 | 主按钮 | 「先看这一站」→ P03（已打卡态） |
| 7 | 次按钮 | 「去认识这一瓣」→ P09 并自动放大这一瓣 |
| 8 | 待同步标记（条件） | 离线打卡时右上角灰标签「待同步」 |

**系统**：打卡记录写入；称号按「今年打过卡的站数」实时计算（04 号第 3 节）；答题时间窗从现在开始 6 小时。

**说明**：打卡成功只代表「到过」，不加同路分。分数只来自答题。

### F2-6 离线打卡与同步

| 步骤 | 界面 | 系统 |
|---|---|---|
| 1 | 没网时进 P04，「我到了」按钮下小字变成「现在没有网络，请扫现场立牌码」，「我到了」置灰 | 没网时不做定位打卡（无法实时校验范围） |
| 2 | 扫立牌码 | 本地校验：码里的站点 ID 与本地离线包里的立牌码列表匹配 |
| 3 | 进 P05，标「待同步」 | 写本地队列：`{type:checkin, board, site, choice, client_time}` |
| 4 | 可以继续看内容、答题，答题记录同样进队列 | 分数在本地显示但标「待同步」 |
| 5 | 恢复网络 | 队列按时间顺序提交；成功后去掉「待同步」，Toast「已恢复网络，记录已同步」 |
| 6 | 服务端拒绝（码已作废、客户端时间与提交时间相差超过 72 小时、同站今年已完成） | 该条记录在 P26 同路册里显示「这次记录没能同步：{原因}」，本地分数回退 |

## M3 站点内容与答题

### F3-1 站点页（P03）

**闭环位置**：L1。起点是进入一站，终点是「记下这一站」（P07）。也是 M6 带货闭环 L3 的起点（底部物产）。

**三种状态**

| 状态 | 判断 | 底部固定按钮 | 「答一答」页签 |
|---|---|---|---|
| 未打卡 | 今年没在这一站打卡 | 「到达打卡」 | 显示题目数量，点进去提示「到现场打卡后才能答题」 |
| 已打卡未完成 | 在 6 小时答题时间窗内，题没答完 | 「继续答题 · 还差 {n} 题」 | 可答 |
| 已打卡未完成、时间窗已过 | 超过 6 小时 | 「再次打卡后继续答题」→ P04 | 提示「答题时间已过，回到现场再打一次卡就能继续」 |
| 已完成 | 今年已答完 | 「看这站好物」 | 显示本人答题结果，可回看讲解，不能重答 |

**页面元素**

| # | 元素 | 说明 |
|---|---|---|
| 1 | 主题大卡（深田青底） | 小字「{站名} · {所在镇}」；主题句；右上角主题字牌；下方梯田等高线纹 |
| 2 | 信息行 | 「约 3 分钟 · 完成可得 30 同路分 · 内容已审定」 |
| 3 | 站点状态条（条件） | 部分开放 / 暂停时显示原因 |
| 4 | 页签 | 导览 / 听一听 / 答一答 / 来源 |
| 5 | 导览 | 3–4 张内容卡（F3-2） |
| 6 | 听一听 | 音频列表（F3-3） |
| 7 | 答一答 | 题目入口或本人结果（F3-4） |
| 8 | 来源 | 本站所有内容的审定单位、审定日期、引用资料；「我发现内容有误」入口 |
| 9 | 这一站的物产 | 2–4 件商品横向卡片 |
| 10 | 这一站的石榴 | 小石榴缩略图 +「{a} 颗籽可以认识」，点了进 P09 并放大这一瓣 |
| 11 | 现场礼仪（条件） | 古城站：文物礼仪；撒玛坝：宴席、乐作礼仪；森林公园：寨神林、防火 |
| 12 | 底部固定按钮 | 见上表 |

**交互**

| 操作 | 反馈 | 系统 |
|---|---|---|
| 切页签 | 内容切换，页签吸顶 | `ev_site_tab` |
| 滚到导览最后一张卡底部 | 无 | 记「看完导览」（用于看完率） |
| 点「我发现内容有误」 | 进 P30，`type=content_error`，自动带上当前页签和卡片 ID | — |
| 点物产卡 | 进 P14，`from_site={site}` | 下单场景记录来源站 |

**验收**：未打卡状态下答一答不能作答；内容卡底部都有审定行；站点暂停时底部按钮置灰并写原因。

### F3-2 导览内容卡

- 每张：插画（16:9）、标题（≤ 16 字）、正文（≤ 120 字）、可选标签（国家级非遗 / 省级非遗 / 节令活动 / 生活习俗 / 手艺）、底部审定行「内容经{单位列表}审定 · {年月}」。
- 卡片可左右滑或上下排列（站点页里上下排列；从石榴进来时左右滑）。

|---|---|---|
| 点一个选项（答对） | 该选项变水田青、出现勾；上方飘「+10」；讲解区展开（绿框，「答对了」+ 讲解 + 来源）；按钮「下一题」 | `POST /quiz/answer`，服务端判分，返回对错、讲解、得分 |

### F6-5 下单与支付（P16、P17）

**闭环位置**：L3。起点是点「立即购买」或「去结算」，终点是支付成功。

**P16 页面元素**：收货方式（寄回家时选地址，用 `wx.chooseAddress`；自提时选自提点和自提日期）；商品清单（按合作社分组，写「由{合作社}发货」）；运费；备注；合计；底部「提交订单并支付」。页面上不出现任何积分、抵扣字样。

| 操作 | 反馈 | 系统 |
|---|---|---|
| 提交 | 按钮加载中 | `POST /orders`：校验库存、价格；锁库存 15 分钟；按合作社拆子订单；返回支付参数 |
| 调起支付 | 微信支付 | `wx.requestPayment` |
| 支付成功 | P17：「付款成功」+ 订单号 + 「{合作社}会在 {48} 小时内发货」+ 按钮「看订单」「继续逛」；同时弹订阅消息授权（发货通知、自提通知） | 支付回调更新订单「待发货」，通知合作社（H01） |
| 用户取消支付 | P17：「还没付款」+「继续付款」（15 分钟内）+「取消订单」 | 订单「待支付」 |
| 15 分钟未付 | — | 自动取消，释放库存 |
| 库存不足 | 弹层「{商品}只剩 {n} 件了」+「改成 {n} 件」/「去掉这件」 | 返回 `STOCK_SHORT` |

### F6-6 订单与物流（P18）

### F6-7 自提

- 自提订单在「已备好」后，订单详情显示自提码（二维码 + 6 位数字，不刷新，订单内唯一）。
- 柜台自提：柜台店员用 S04 扫码核销。营地自提：营地工作人员同样用店员端（后台给营地配置一个「柜台」）。
- 超过自提日期 3 天未取：提醒一次；7 天未取：运营联系，可改寄或退款。

### F6-8 售后（P19）

| 类型 | 条件 | 流程 |
|---|---|---|
| 未发货退款 | 待发货 | 游客提交 → 自动同意 → 原路退款 → 合作社端该单变「已取消」 |
| 退货退款 / 仅退款 / 补发 | 发货后、签收 7 天内 | 游客选原因、上传最多 3 张照片 → 合作社 24 小时内回应（同意 / 补发 / 说明）→ 运营审核（H03 与 A6-4）→ 退款或补发 → 关闭 |

## M7 问驮驮

### F7-1 问驮驮（P12）

**闭环位置**：问答闭环 L5 的游客侧。起点是提问，终点是得到审定过的答案，或得到柜台电话、问题被记下。

**页面元素**：顶部吉祥物 + 气泡「我只回答县里审定过的问题。答不上的，会告诉你去问谁。」；常见问题胶囊（后台配置，最多 8 个）；对话区；底部输入框（≤ 50 字）+ 发送。

**交互与系统**

| 步骤 | 界面 | 系统 |
|---|---|---|
| 点常见问题胶囊 | 作为用户提问发出 | 直接取该问答 |
| 输入并发送 | 用户气泡出现；驮驮「思考」形象 0.5 秒 | `POST /ask`：1）敏感词匹配；2）问答库检索（关键词 + 同义词，取最高分）；3）分数 ≥ 阈值则命中 |
| 命中 | 驮驮气泡：答案 + 绿色来源行「来源：{单位} · 已审定」；答案里可带按钮（跳站点、跳服务地图、拨电话）；气泡下「有用 / 没用」 | 记录问题、命中的问答 ID |
| 没命中 | 驮驮气泡：「这个问题还没有审定过的说法，可以问柜台工作人员：」+ 最近柜台的电话按钮（用户今天打过卡的站优先，否则游客中心）+ 灰字「你的问题已记下，整理审定后会补上」 | 写入「未答问题」，同义问题合并计数 |
| 敏感词命中 | 驮驮气泡：标准回复「这个问题我不方便回答。关于红河的民族文化，可以看看各站经过审定的介绍。」+「去看四站」 | 不检索；记录，标「敏感」 |
| 点「没用」 | 气泡下出现「谢谢，我们会改进」 | 该问答「没用」计数 +1，进 B7 待优化 |
| 问题过长 / 空 | 发送按钮置灰 | — |

**规则**：对话不保存到云端给其他用户看；同一用户本地保留最近 20 条，退出登录后清空。一期不接任何生成式模型。
