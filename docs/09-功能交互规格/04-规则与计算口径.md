# 规则与计算口径

> 本文件是计分、档位、称号、籽状态、时间窗、离线同步、去重、下线影响、统计指标的**唯一口径**。前端只做展示，所有判断都在服务端完成；前端本地计算（离线时）必须与本文件一致，联网后以服务端结果为准。
> 可配置参数在后台 A1-4 修改，默认值见附录。

---

## 1. 时间与年度

| 项 | 口径 |
|---|---|
| 时区 | 一律北京时间（UTC+8），服务端存 UTC，计算时转换 |
| 年度 | 自然年：1 月 1 日 00:00:00 – 12 月 31 日 23:59:59 |
| 跨年 | 以**服务端收到并确认**的时间判断归属年度；离线记录以 `client_time` 归属年度，但 `client_time` 不得早于服务端时间 72 小时（见第 6 节） |
| 年度重置 | 1 月 1 日起：打卡、答题、同路分、称号、可领档位、领礼资格全部从零开始；往年记录保留可查（P25 年份切换、P26 往年同路册） |
| 「今天」 | 首页「今天正在进行的站」按北京时间自然日，只看本地记录 |

## 2. 打卡

### 2.1 判定顺序

服务端按顺序判断，命中即返回（与 01 号 F2-2 一致）：

| 顺序 | 结果码 | 条件 | 写记录 |
|---|---|---|---|
| 1 | `SITE_CLOSED` | 站点开放状态 = 暂停 | 写一条「尝试」记录（用于统计），不写打卡 |
| 2 | `MOVING` | 定位打卡且 `speed > 速度阈值`（默认 3 m/s ≈ 10.8 km/h）；`speed < 0`（设备不支持）视为 0 | 写「尝试 · 行驶中」，计入「行驶中打卡被拦」指标 |
| 3 | `WEAK_SIGNAL` | 定位打卡且 `accuracy > 精度阈值`（默认 200 m） | 写「尝试 · 信号弱」 |
| 4 | `NOT_ARRIVED` | 定位打卡且距离 > 半径，或落在禁止区域内 | 写「尝试 · 未到」，保存距离（取整到 100 m） |
| 5 | `ALREADY_DONE` | 今年本站已「完成」（2.3） | 不写 |
| 6 | `REOPENED` | 今年本站已打卡但未完成 | 不新增打卡记录；刷新答题时间窗 |
| 7 | `OK` | 以上都不是 | 写打卡记录 |

- 扫立牌码打卡（`method=board`）跳过 2、3、4，但校验立牌码：存在、未作废、所属站点与请求一致（不一致以码为准）。
- 「我已停稳 / 我是乘客」必填，未选服务端返回 `CHOICE_REQUIRED`（前端已拦截，兜底）。
- 距离计算：Haversine 公式，GCJ-02 坐标直接计算（四站范围内误差可忽略）。

### 2.2 频率限制

| 限制 | 默认 | 超出时 |
|---|---|---|
| 同一用户同一站 1 分钟内提交 | ≤5 次 | `TOO_FREQUENT`，「操作太快了，稍等一下」 |
| 同一用户 1 小时内在不同站 `OK` | 两站间距离 / 时间差 > 120 km/h 视为异常 | 仍返回 `OK`，但记异常标记，进 A5-7 观察（不打扰游客） |

### 2.3 站点「完成」

**本站完成 = 今年在本站打过卡 且 本站 3 道题全部「已结算」**。

题目「已结算」：答对，或答错后点了「我记住了」。答错未点「我记住了」= 未结算。

### 2.4 答题时间窗

- 打卡成功（`OK` 或 `REOPENED`）时打开，持续 **6 小时**。
- 时间窗内可答本站题（包括 P10 籽的题）。
- 过期后提交答案返回 `QUIZ_WINDOW_EXPIRED`；重新打卡（任何方式）返回 `REOPENED`，时间窗重开 6 小时。
- 「我记住了 +3」不受时间窗限制（答错已发生，只差确认讲解）。
- 目的：保证「到现场才能答」，又不逼人在停车场答完。

## 3. 称号

按**今年打过卡的站数**（不要求完成）：

| 站数 | 称号 |
|---|---|
| 0 | 无（显示「还没有称号」） |
| 1 | 红河来客 |
| 2 | 红河同路人 |
| 3 | 红河熟客 |
| 4 | 长廊同心人 |

- 称号只升不降（同一年内）；年度重置后从无开始。
- 「四瓣全亮」= 称号「长廊同心人」，两者同一个判断。
- 称号与礼品档位**相互独立**：称号看到没到，档位看完没完成、分够不够。

## 4. 石榴籽状态

### 4.1 籽的内容状态（后台，全体用户相同）

| 状态 | 条件 |
|---|---|
| 未设置 | 后台没有这颗籽的记录 |
| 整理中 | 有记录，但非遗卡或关联题目任一未上线 |
| 可认识 | 非遗卡已上线 且 至少一道关联题目已上线 |
| 目录 | 迤萨路口这一瓣的 5 颗籽，固定为目录型 |

### 4.2 籽对某个用户的显示状态

| 显示 | 条件 |
|---|---|
| 米色 | 用户今年没在该站打卡 |
| 石榴红 | 已打卡 + 籽为「可认识」+ 用户未认识 |
| 红 50% + 虚线 | 已打卡 + 籽为「整理中」 |
| 红 + 金边（已认识） | 已打卡 + 用户**看完该籽的非遗卡**（滚到最后一张底部或听完任一音频）**且**该籽关联题目中至少一道已结算 |
| 红 + 小点 | 迤萨路口目录籽，用户打开过 |

- 「已认识」一旦达成，本年度保留；籽后来被下线变「整理中」，用户端仍显示金边（不收回）。
- 籽的题与站点题共用，不额外计分。
- 统计「认识 {m} 颗籽」只数金边籽，不含目录籽。

## 5. 同路分与礼品档位

### 5.1 计分

| 行为 | 得分 |
|---|---|
| 答对 | 10 |
| 答错 + 「我记住了」 | 3 |
| 答错未确认 | 0（未结算） |
| 打卡、看内容、听音频、认识籽、分享、下单 | 0 |

- 每站 3 题，单站 9–30 分，四站最高 120 分。
- 年度同路分 = 今年所有已结算题目得分之和。
- 题目被下线：已得分保留；未答的替换为同站另一道已上线题（替换后仍为 3 题）。同站上线题不足 3 道时，不足部分视为「已结算 · 10 分」（不让游客因为后台下线而吃亏），并在后台告警。
- 同路分不能提现、不能抵现金、不能在商城里抵扣、不能转赠。

### 5.2 档位

| 档位 | 完成站数 | 年度同路分 |
|---|---|---|
| 一档 · 一站礼 | ≥1 | — |
| 二档 · 同路礼 | ≥2 | ≥40 |
| 三档 · 熟客礼 | ≥3 | ≥70 |
| 四档 · 同心礼 | 4 | ≥100 |

- **可领档位** = 同时满足两个条件的最高一档。
- 例：完成 2 站共 39 分 → 一档；完成 3 站共 60 分 → 二档（不够 70）。
- 「还差」提示：对下一档，分别算还差几站、还差几分；两项都差时都写（「还差 1 站 / 12 分」）。

### 5.3 领礼资格

| 规则 | 口径 |
|---|---|
| 每证每年一次 | 以证件哈希为准；当年领过任何一档后，该证件当年不能再领 |
| 取当时最高档 | 核销时服务端重新计算可领档位，以核销那一刻为准（游客出码后又完成一站，店员扫到的是新档位） |
| 不补差 | 领了二档后再走两站，不能补领四档 |
| 本人分数 | 档位按「本人」证件绑定的微信号的分数计算；一个微信号只能绑定一个「本人」证件 |
| 降档 | 柜台不能发高档时可以降档发放，须游客端确认（02 号 S02 `TIER_NOT_HERE`）；降档领取同样占用当年资格 |
| 柜台 | 只能在该档「可领柜台」核销 |
| 撤销 | 撤销成功后资格恢复（02 号 S02-R） |
| 暂停资格 | 后台「标记异常」的用户不能出码 |

### 5.4 领礼令牌

| 项 | 口径 |
|---|---|
| 生成 | `POST /gift/token`：服务端生成随机令牌（128 位），二维码内容 `G.{令牌}`；同时生成 6 位数字码，数字码在全局有效令牌中唯一 |
| 有效期 | 30 秒；新令牌签发时旧令牌立即失效 |
| 状态 | `ISSUED` → `SCANNED`（锁定 60 秒）→ `REDEEMED` / 回到 `ISSUED` / `EXPIRED` |
| 锁定中过期 | 已被店员扫到（`SCANNED`）的令牌，在锁定期内不因 30 秒到期而失效，游客端暂停刷新 |
| 数字码防爆破 | 同一店员 1 分钟内输错 5 次，锁 5 分钟 |

## 6. 离线与同步

| 项 | 口径 |
|---|---|
| 能离线做的事 | 看已下载站点的内容、听音频、扫码打卡、答题（本地判分，题目与答案在离线包中加密存放）、看石榴 |
| 不能离线做的事 | 定位打卡、领礼出码、核销、下单支付、证件登记、反馈 |
| 离线打卡 | 只能扫立牌码；本地用离线包里的立牌码表校验（码 ID、站点、是否作废，以离线包生成时为准） |
| 离线答题 | 本地判分并显示「待同步」；离线包内题目是该用户已锁定的 3 题（下载离线包时需要登录，未登录下载的离线包不含题目，答一答显示「登录并联网后可答」） |
| 本地队列 | 按 `client_time` 顺序存：打卡、答案、确认讲解、看完内容、认识籽；每条带本地生成的 `request_id` |
| 同步 | 恢复网络后自动按顺序提交；服务端用 `request_id` 去重 |
| 拒绝条件 | 立牌码已作废（以服务端为准）；`client_time` 早于服务端时间 72 小时以上或晚于服务端时间 5 分钟以上；同站今年已完成；离线包版本过旧导致题目已被替换（该题按 5.1 下线规则处理，不判错） |
| 拒绝后 | 同路册里该条显示「这次记录没能同步：{原因}」；本地分数回退；不影响其他记录 |
| 时间窗 | 离线打卡的时间窗从 `client_time` 起算 |

## 7. 去重与幂等

| 场景 | 去重键 | 行为 |
|---|---|---|
| 打卡 | 用户 + 站 + 年 | 已有打卡则返回 `REOPENED` / `ALREADY_DONE`，不新增 |
| 答题 | 用户 + 题 + 年 | 已答返回原结果，不重复计分 |
| 我记住了 | 用户 + 题 + 年 | 已确认返回成功 |
| 证件登记 | 证件哈希（全局） | 被其他微信号占用返回 `ID_TAKEN` |
| 核销确认 | `request_id` | 同一 `request_id` 返回同一结果；数据库对「令牌 ID」唯一约束 |
| 自提交货 | `request_id` + 订单 | 同上 |
| 下单 | 前端 `request_id` | 5 分钟内同一 `request_id` 返回同一订单 |
| 支付回调 | 微信 `transaction_id` | 重复回调直接返回成功 |
| 退款 | 售后单 ID | 一个售后单只发起一次退款请求，失败人工处理 |
| 未答问题 | 归一化文本（去标点、空格、语气词）+ 相似度 ≥ 0.85 | 合并计数 |

**证件哈希**：`HMAC-SHA256(pepper, 证件类型 + ":" + 规范化证件号)`。规范化：去空格、字母转大写；身份证末位 x 转 X。pepper 存密钥管理服务，不进代码库、不进数据库。

## 8. 内容下线的影响

| 被下线的对象 | 连带影响 | 对游客已有数据 |
|---|---|---|
| 内容卡 | 引用它作讲解的题目下线；关联籽可能回到「整理中」；离线包标记落后 | 「看完导览」记录保留；再看时显示「该内容正在更新」 |
| 题目 | 未答的用户替换新题（5.1） | 已得分保留 |
| 音频 | 从列表消失 | 「听完」记录保留 |
| 非遗卡 | 籽回到「整理中」 | 已认识保留金边 |
| 籽 | 显示为「整理中」 | 同上 |
| 问答 | 不再匹配 | — |
| 商品 | 停售；购物车、心愿单中显示「已下架」 | 已付款订单照常履约 |
| 素材到期 | 引用它的内容自动下线（按上面各行处理） | — |
| 站点暂停 | 不能打卡、不能领该站柜台礼品；内容照常可看 | 无影响 |

## 9. 统计指标口径（B8）

| 指标 | 口径 |
|---|---|
| 到访人数 | 当日打卡结果为 `OK` 或 `REOPENED` 的去重用户数；按站、按天 |
| 单站完成率 | 当期在该站打卡的用户中，该站「完成」（2.3）的比例 |
| 看完率 | 打卡用户中「看完导览」（滚到最后一张卡底部）的比例 |
| 平均得分 | 完成该站用户的站内得分平均值 |
| 领礼人数 | 当期 `REDEEMED` 且未撤销的记录数（= 人数，每证一次） |
| 只走 1–2 站的领礼比例 | 领礼记录中，领取时完成站数为 1 或 2 的比例 |
| 订单数 / 金额 | 已付款订单（含后来退款），金额为实付；另列「净额」= 实付 − 退款 |
| 按站带动 | 订单 `from_site` 分组；无 `from_site` 的记为「直接购买」 |
| 复购率 | 当年下单 ≥2 次（不同自然日）的用户 / 当年下单用户 |
| 退款率 | 当期退款订单数 / 当期已付款订单数 |
| 内容审定覆盖率 | 线上内容中，审定记录完整（每个必经环节都有通过记录）的比例 |
| 行驶中打卡被拦次数 | 结果码 `MOVING` 的尝试次数 |
| 问驮驮答上率 | 提问中命中问答库（含敏感词标准回复）的比例 |
| 渠道 | 首次进入时的 `ch` 参数，归属到用户当天会话 |
