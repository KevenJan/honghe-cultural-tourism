# 运营后台 · 功能交互规格

> 写法见 [README](README.md) 第 1 节。后台原则：**游客能看到的每样东西，后台都有地方管；每个关键动作，后台都有记录**。
> 页面编号 `A模块-序号` 与左侧菜单一一对应。接口前缀 `/admin/api/v1`，字段定义见 10 号文件。

---

## 0. 通用约定

### 0.1 布局

- 电脑浏览器，最小宽度 1280。左侧菜单（B1–B8 八个一级菜单），顶栏：当前账号、角色、「待我处理」铃铛（数字）、退出。
- 登录：账号 + 密码 + 短信验证码（或企业微信扫码，二选一，二期）。密码 ≥10 位含字母数字；连续 5 次错误锁 30 分钟；30 分钟无操作自动退出。
- 领导查看账号登录后直接进 A8-1，只看到 B8 菜单。

### 0.2 列表页统一结构

| 区域 | 规则 |
|---|---|
| 筛选区 | 关键字 + 2–4 个下拉；「查询」「重置」；筛选条件写进 URL，刷新不丢 |
| 操作区 | 左：「新增」等主操作；右：「导出」（只导出当前筛选结果，≤5 万行，异步生成，完成后在铃铛里下载） |
| 表格 | 默认每页 20，可选 50/100；列可排序的标注 ↕；操作列固定在右侧 |
| 批量 | 勾选后出现批量操作条（批量上下线、批量导出）；批量操作要二次确认，写清影响数量 |
| 空 | 「暂无数据」+ 主操作按钮 |

### 0.3 表单统一规则

- 必填项标红星；失焦即校验，错误红字写在字段下方；提交时滚动到第一个错误。
- 离开未保存的表单弹「有未保存的修改，确定离开？」。
- 富文本只用于公告和文章：只允许标题、加粗、列表、图片、链接（只允许本小程序页面）。内容卡正文用纯文本 + 字数计数。
- 图片上传：jpg/png/webp，≤5 MB，上传后自动生成 3 档尺寸；必须从素材库选或上传时同时登记授权（见 A2-8）。
- 所有保存操作写入操作日志（A1-3）：谁、何时、哪条、改前改后（JSON diff）。

### 0.4 删除

业务数据一律不物理删除：内容用「下线」，账号用「停用」，记录用「作废」。只有「草稿」状态的内容可以删除。

### 0.5 权限矩阵

✓ 可操作；👁 只读；— 看不到。「本柜台」「本单位」表示数据范围受限。

| 菜单 | 系统管理员 | 运营人员 | 审定员 | 柜台主管 | 领导查看 |
|---|---|---|---|---|---|
| A1 工作台 | ✓ | ✓ | ✓（只有待审） | ✓（本柜台） | — |
| A1 账号与角色、系统设置 | ✓ | — | — | — | — |
| A1 操作日志 | ✓ | 👁（只看自己） | — | — | — |
| A2 内容中心 | 👁 | ✓ | 👁 | — | — |
| A3 审定中心 | 👁 | ✓（提交、紧急下线） | ✓（本单位环节） | — | — |
| A4 站点与安全 | 👁 | ✓ | — | 👁（本站开放状态可改） | — |
| A5 礼品与核销 | 👁 | ✓ | — | ✓（本柜台库存、店员、撤销审批） | — |
| A6 商城与合作社 | 👁 | ✓ | — | — | — |
| A7 用户与服务 | 👁 | ✓ | ✓（只有分给本单位的纠错和问答审定） | — | — |
| A8 数据看板 | ✓ | ✓ | 👁（内容相关） | 👁（本柜台） | 👁 |

## B1 工作台与权限

### A1-1 工作台

**闭环位置**：所有闭环的「待办汇总」。每个闭环卡住的地方都在这里冒出来。

| 区域 | 内容 | 点击去向 |
|---|---|---|
| 待我处理 | 待审内容 {n}、待处理留言 {n}、内容纠错 {n}、库存预警 {n}、补货申请 {n}、撤销审批 {n}、售后待审 {n}、发货超时 {n}、未答问题（本周新增）{n}、合作社上架申请 {n}、对账疑问 {n} | 对应列表页，已带筛选条件 |
| 今日概况 | 打卡人数、领礼数、订单数与金额、问驮驮提问数；与昨日比 | A8-1 |
| 站点状态 | 四站开放状态、置顶公告 | A4-4、A4-3 |
| 系统提醒 | 立牌码近 7 天扫码数为 0 的站（可能被遮挡或损坏）、素材授权 30 天内到期、离线包版本落后 | 对应页面 |

不同角色只看到自己有权限的待办。待办数为 0 的项隐藏。

### A1-2 账号与角色

**列表列**：姓名、账号、角色、所属单位 / 柜台、手机号（中间 4 位打码）、状态、最后登录、操作（编辑、停用 / 启用、重置密码）。

**表单**：姓名*、手机号*、角色*（单选）、所属单位（审定员必选：文化馆 / 民宗局 / 文物部门 / 文旅局）、所属柜台（柜台主管必选）、备注。

**规则**：系统管理员至少保留 2 个；停用账号不删除；角色改变立即生效（下次请求即校验）。审定员账号的单位决定他能审哪个环节。

### A1-3 操作日志

**筛选**：时间范围、操作人、模块、操作类型（新增 / 修改 / 上线 / 下线 / 审定 / 核销 / 撤销 / 退款 / 导出 / 登录）、对象 ID。

**列**：时间、操作人、角色、模块、操作、对象、摘要；点开看改前改后对比。

**规则**：只能追加，不能修改和删除（数据库层面单独表、应用账号无 UPDATE/DELETE 权限）；保留 3 年；「导出」本身也记日志。

### A1-4 系统设置（配置项）

所有可配置参数集中在这里，改动需二次确认并写日志。默认值见 [`04-规则与计算口径.md`](04-规则与计算口径.md) 附录。

| 分组 | 配置项 |
|---|---|
| 打卡 | 速度阈值（米/秒）、精度阈值（米）、定位超时（秒）、答题时间窗（小时）、离线记录最长有效（小时） |
| 计分 | 答对分、答错分（看讲解后）、每站题数 |
| 领礼 | 令牌有效期（秒）、核对锁定时长（秒）、撤销时限（分钟）、证件每年可重登次数 |
| 商城 | 未付款自动取消（分钟）、默认发货时限（小时）、自动确认收货（天）、售后申请期（天）、合作社回应时限（小时）、对账确认期（天） |
| 问驮驮 | 匹配阈值、未答问题合并相似度 |
| 通知 | 短信签名、各类通知开关 |

## B2 内容中心

> 所有内容类对象（站点介绍、内容卡、音频、题目、石榴籽、非遗卡、问答）共用同一套**版本 + 审定**机制：编辑已上线内容会生成新版本草稿，线上继续显示旧版本，直到新版本审定发布。

### A2-1 站点

**列表**：四站固定，不能新增删除（二期支线再开放新增）。列：站名、主题字、主题句、开放状态、内容卡数（已上线 / 总数）、题目数、石榴籽数、关联商品数、操作（编辑）。

**表单字段**

| 字段 | 规则 |
|---|---|
| 站名*、英文名 | ≤10 字 |
| 主题角标* | 同一条路 / 同一沟水 / 同一条街 / 同一片田 |
| 主题句* | ≤20 字 |
| 插画* | 从素材库选，横版 750×500 以上 |
| 停车点名称*、停车点说明* | 说明写「游客真正站着的地方」，≤60 字 |
| 开放时间* | 文本，如「全天」「08:30–18:00」 |
| 防火提示 | 开关 + 文本；森林公园默认开 |
| 关联物产 | 选商品，2–4 件，排序 |
| 关联柜台 | 选柜台（A5-3） |

站点介绍文字改动走审定；插画、停车点、开放时间等事实信息运营可直接改（写日志）。

### A2-2 内容卡

**列表筛选**：站点、审定状态、关键字。**列**：标题、站点、顺序、字数、审定状态、版本、上线时间、操作（编辑、提交审定、预览、下线、查看审定记录）。

**表单字段**

| 字段 | 规则 |
|---|---|
| 站点* | 单选 |
| 标题* | ≤14 字 |
| 正文* | 纯文本，≤120 字，实时字数；超出不能保存 |
| 插画 | 素材库，必须「已授权」 |
| 引用县情数据 | 正文里用 `{县情:人口}` 这样的占位符插入，渲染时替换；占位符必须存在于 A2-7 |
| 顺序* | 站内排序 |
| 关联音频 | 可选 |
| 审定提示 | 是否涉及古城（勾选后审定链加文物部门） |

**预览**：右侧手机框实时预览（与小程序同一套渲染组件）。

### A2-3 音频

字段：站点*、标题*、文件*（mp3，≤3 分钟，≤5 MB，上传后自动读时长，超 3 分钟拒绝）、文字稿*（必填，无文字稿不能提交审定）、讲述人*、授权书编号*（从 A2-8 选已登记的授权）、语言（普通话 / 方言 / 族语；非普通话需附普通话译文）。

### A2-4 题目

**表单字段**

| 字段 | 规则 |
|---|---|
| 站点* | — |
| 题干* | ≤40 字 |
| 选项* | 2–4 个，每个 ≤16 字；正确项单选 |
| 讲解* | ≤80 字；必须选「引自内容卡」（下拉选同站已上线或同批送审的内容卡），否则不能提交 |
| 关联石榴籽 | 可选；关联后这道题也是该籽的「认识」题 |
| 难度 | 易 / 中（只用于统计） |

**规则**：每站上线题目 ≥3 道（游客每年每站抽 3 道；题库大于 3 道时按用户随机抽并固定）。被引用的内容卡下线 → 题目同步下线。

### A2-5 石榴籽

**矩阵视图**：行 = 四站，列 = 民族（汉、哈尼、彝、傣、瑶、拉祜……按县情），格子显示状态色（灰 未设置 / 黄 整理中 / 绿 可认识 / 红 已下线）。点格子编辑。

字段：站点*、民族*、状态（由审定结果决定，不能手改为「可认识」）、一句话*（≤30 字）、非遗卡（选 A2-6）、和谁一起（选同站其他民族的籽，用于「按一件事看」）、关联题目（选 A2-4）。

**规则**：「可认识」= 非遗卡已上线 且 关联题目已上线；任一下线，状态自动回「整理中」。

### A2-6 非遗卡

字段：名称*、级别*（国家级 / 省级 / 州级 / 县级 / 节令活动 / 生活习俗 / 手艺）、出处*（级别为非遗名录时必须填名录批次和编号）、正文*（≤200 字）、图片、音频（可选）、相关好物（选商品）。

### A2-7 县情数据

键值表：键（如 `人口`）、值、单位、年份、出处*、更新人、更新时间。修改后列出「引用这个数据的内容卡 / 题目 {n} 条」，确认后这些对象**不需要重新审定**（数据本身经统计部门出具），但会写日志。

### A2-8 素材库

**列**：缩略图、名称、类型（图片 / 音频 / 纹样 / 视频）、来源、授权状态（已授权 / 授权中 / 未授权 / 已过期）、授权书编号、到期日、被引用次数、操作。

**规则**：未授权、已过期素材不能被选用；到期前 30 天提醒；到期后引用它的内容自动下线并通知运营。上传时必填：来源（自拍 / 甲方提供 / 传承人提供 / 购买）、权利人、授权范围、到期日（可选「永久」）、授权书扫描件。

### A2-9 首页大图

字段：图片*（750×420）、标题*（≤12 字）、说明（≤20 字）、按钮文字（≤6 字）、跳转类型*（站点 / 同心石榴 / 商品 / 公告 / 文章）、跳转目标*、上线时间*、下线时间*、排序。最多同时上线 3 张；不允许外链。

## B3 审定中心

### A3-1 审定列表

**页签**：待我审（审定员默认）、我已审、全部（运营）。

**列**：对象类型、标题、站点、提交人、提交时间、当前环节、已等待天数（>3 天橙，>7 天红）、操作（去审定）。

**审定链**（与 08 号 B3 一致）

```
草稿 → 待文化馆审 → 待民宗局审 → [待文物部门审，仅古城] → 待文旅局发布 → 已上线
任一环节退回 → 退回草稿（带意见）
已上线 → 申请下线（任一审定单位）/ 紧急下线（运营）→ 已下线 → 修改后重新从草稿开始
```

**批量提交**：运营可把同一站的多条内容打包成「一批」提交，审定员可整批看、逐条审；整批通过才发布（避免一站内容半新半旧）。

### A3-2 审定详情

| 区域 | 内容 |
|---|---|
| 左：手机预览 | 与小程序一致的渲染；可切换「新版本 / 线上版本」 |
| 中：修改对比 | 与上一版本逐字对比（新增绿、删除红） |
| 右：审查要点（勾选） | 是否落到共同性；有无罗列差异或猎奇化；族语是否以普通话为主并有译文；级别标签是否有出处；数据是否引自县情数据；图片是否已授权；（文物）是否涉及攀爬、触摸、拓印等不当引导 |
| 下：意见与记录 | 历次意见；本次意见输入框 |
| 按钮 | 「通过」「退回」（必须写意见 ≥5 字）；文旅局环节为「发布」「退回」 |

**规则**：审查要点全部勾选才能点「通过」；每次操作记录审定人、单位、时间、意见，永久保存；发布后内容卡底部审定标注自动生成「内容经县民宗局、文旅局、文化馆审定 · {年} 年 {月} 月」。

**通知**：进入某环节时短信 + 后台铃铛通知该单位审定员；超过 3 天未审，再提醒一次并抄送运营。

### A3-3 下线管理

| 操作 | 谁 | 流程 | 影响 |
|---|---|---|---|
| 申请下线 | 任一审定员 | 写原因 → 运营确认 → 下线 | 见下 |
| 紧急下线 | 运营 | 写原因 → 立即下线 → 事后通知全部审定单位 | 同下 |
| 一键下线影响 | — | 弹窗先列出影响：关联题目 {n}、石榴籽 {n}、离线包 {n} 站需重新生成 | 关联题目、籽状态同步下线；游客已得分数保留；游客看过的卡片显示「该内容正在更新」；离线包版本 +1 |

**列表**：已下线内容、下线时间、下线人、原因、是否已修改重新送审。

## B4 站点与安全

### A4-1 打卡范围

地图组件（腾讯地图 JS API），每站：中心点（拖动标记或输入经纬度）、半径（50–1000 米，滑块）、圆形范围实时显示；可叠加「禁止区域」多边形（匝道、主路、滑塌冲沟），中心点 + 半径与禁止区域重叠时红色警告，不能保存。

保存后显示「近 7 天：打卡成功 {n}、还没到 {m}、信号弱 {k}」，用于调整半径。

### A4-2 现场立牌码

**列**：码编号、站点、立牌位置说明、生成时间、状态（有效 / 已作废）、近 7 天扫码数、操作（下载、作废）。

| 操作 | 规则 |
|---|---|
| 生成 | 选站点、填位置说明 → 调微信 `getUnlimitedQRCode`，`scene=b{码ID}` → 生成可打印 PDF（按 `materials/立牌制作规范.md` 尺寸，含站名、提示语） |
| 作废 | 写原因（损坏 / 被遮挡 / 疑似被替换）→ 立即失效；扫旧码的游客见「这个码已经更换，请扫现场的新码」 |
| 监控 | 近 7 天扫码数为 0 且该站有打卡 → 工作台提醒「立牌可能被遮挡或损坏」 |

### A4-3 公告

字段：标题*（≤20 字）、正文*（富文本 ≤500 字）、类型*（普通 / 置顶）、范围（全县 / 指定站点）、上线时间*、下线时间*。置顶公告同时只能有 1 条；置顶公告游客不能关闭。

### A4-4 开放状态

四站一屏：每站三选一（开放 / 部分开放 / 暂停）+ 原因*（非开放时必填，≤30 字）+ 预计恢复时间（可选）。保存后立即生效（游客端缓存 ≤1 分钟）。柜台主管可改本站。

### A4-5 安全参数

即 A1-4 的「打卡」分组的快捷入口，另显示「行驶中打卡被拦」近 30 天曲线。

### A4-6 离线包

**列**：站点、当前版本、生成时间、大小、包含内容数、状态（最新 / 落后于线上内容）、操作（重新生成、下载核对）。

内容上线或下线后状态变「落后」，工作台提醒；点「重新生成」异步打包（内容卡、音频、题目、插画、服务点、立牌码校验表），完成后版本 +1，游客端下次联网提示更新。

### A4-7 服务点

字段：名称*、类型*（停车场 / 厕所 / 服务柜台 / 医疗点 / 充电桩 / 求助电话点）、所属站点、坐标*（地图选点）、开放时间、电话、备注。批量导入：用 `materials/templates/服务点与电话.csv`。

## B5 礼品与核销

### A5-1 档位规则

四档固定，每档可改：档名、所需站数*、所需分数*、可领柜台*（多选）、可选礼品（从 A5-2 选）、启用状态。改动对「今天起」的领取生效，已领记录不变；改动写日志，并在工作台提醒「档位规则已调整，请同步告知柜台」。

### A5-2 礼品

字段：名称*、图片*、所属档位*、供应合作社（选 A6-1，可空）、单价*（对账用）、描述（≤30 字）、状态。

### A5-3 柜台与库存

**柜台字段**：名称*、类型*（礼品柜台 / 自提点 / 两者）、所属站点*、地址*、开放时间*、主管*、电话、状态。

**库存矩阵**：行 = 柜台，列 = 礼品，格子 = 余量（低于预警线橙色）；点格子：「入库」（数量、批次、备注）、「调拨」（转到另一柜台）、「盘点」（填实盘数，差异写原因）、「改预警线」。所有变动生成库存流水，可查。

### A5-4 补货与预警

列表：柜台、礼品、当前余量、预警线、来源（自动预警 / 店员报补货）、提出时间、状态（待处理 / 已安排 / 已到货）。运营「安排补货」→ 填预计到货日期 → 到货后在 A5-3 入库，关联此单自动关闭。

### A5-5 店员

列：姓名、柜台、角色（店员 / 主管）、手机号（打码）、绑定状态（未绑定 / 已绑定）、今日发放、状态、操作（生成绑定码、停用、换柜台）。绑定码为小程序码图片，24 小时有效，可直接发给店员。

### A5-6 核销记录与撤销

**筛选**：时间、柜台、店员、档位、礼品、状态（已发放 / 已撤销）。**列**：时间、柜台、店员、档位、礼品、领取人（张* · 后四位）、状态、操作（详情、撤销）。

**撤销审批页签**：待审批的撤销申请；运营可审批任意柜台，主管只能本柜台。运营在此也可对超过 10 分钟的记录做「后台更正」，必须写原因。

**导出**：按柜台、按日；导出内容中领取人已脱敏。

### A5-7 异常提醒

| 规则（默认，A1-4 可配） | 级别 |
|---|---|
| 同一店员 10 分钟内发放 ≥15 份 | 中 |
| 同一证件哈希 1 天内被扫 ≥3 次（不同柜台） | 中 |
| 店员一天撤销 ≥3 次 | 中 |
| 「证件对不上」记录 | 低 |
| 柜台盘点差异 ≥5 | 高 |

处理：查看 → 标记「已核实，无问题」/「已处理」（写说明）。

## B6 商城与合作社

### A6-1 合作社

字段：名称*、类型（合作社 / 手艺人 / 企业）、负责人*、电话*、所在乡镇村*、统一社会信用代码或身份证（手艺人）、资质文件（营业执照、食品经营许可等，上传扫描件 + 到期日）、收款信息*（户名、开户行、账号，加密存储，仅系统管理员和财务角色可见完整）、合同起止、服务费比例、账号（最多 3 个微信，生成绑定码）、状态。

**指标页签**：近 90 天订单数、超时发货率、退款率、评价均分。超时率 >20% 或退款率 >10% 标红。

### A6-2 商品与来源档案

**列表**：图、名称、合作社、品类、价格、关联站点、库存、状态（草稿 / 待审核 / 在售 / 已下架）、来源档案批次、操作。

**表单字段**

| 字段 | 规则 |
|---|---|
| 名称*、品类* | — |
| 图片* | 实拍 ≥3 张，第一张为主图 |
| 价格* | 只有一个价格，不允许划线价 |
| 规格* | 最多 5 个规格，每个有价格和库存 |
| 关联站点* | 至少一站 |
| 来源档案* | 生产者、产地村寨、采收或制作时间、批次号、照片；无档案不能上架 |
| 配送方式* | 寄回家 / 柜台自提 / 营地自提（多选）；可寄范围 |
| 发货时限 | 默认 48 小时 |
| 保质期、储存方式 | 食品必填 |
| 是否耐储、是否生鲜 | 生鲜不支持「不想要了」退货 |
| 防火商品检查 | 森林公园关联商品不能为明火类（打火机、炭、蜡烛等），提交时提示人工确认 |
| 首页推荐、排序 | — |

**合作社申请**：H05 的上下架、新批次申请进入「待审核」页签；运营核实（可电话或实地）后通过或退回。

### A6-3 订单

**筛选**：时间、状态、合作社、下单场景（站点）、配送方式、订单号、收货手机尾号。

**列**：订单号、下单时间、商品、金额、合作社、配送方式、下单场景、状态、剩余发货时间、操作（详情、代发货、代备货、取消并退款）。

**订单状态机**

```
待付款 ─15分钟未付─→ 已取消
待付款 ─付款─→ 待发货（寄）/ 待备货（自提）
待发货 ─填单号─→ 已发货 ─游客确认或 10 天─→ 已完成
待备货 ─合作社点「已备好」─→ 已备好（待取货）─柜台核销─→ 已完成
待发货 / 待备货 ─未发货退款─→ 已取消（已退款）
已发货 / 已完成（7 天内）─售后─→ 售后中 ─→ 回到原状态或已退款
```

**代操作**：运营可代合作社发货、备货，记录标「运营代操作 · {运营姓名}」。

### A6-4 售后

**列**：售后单号、订单号、类型、原因、金额、合作社、状态、合作社回应、剩余时间、操作（审核）。

**审核页**：游客描述与照片、合作社回应、订单时间线、物流；按钮「同意退款」「同意补发」「驳回」（必须写原因，游客端可见）。同意退款后调用微信退款接口，结果回写；失败进入「退款异常」页签人工处理。

### A6-5 对账结算

**列表**：月份、合作社、订单数、商品金额、退款、服务费、礼品供货、应结金额、状态（待确认 / 有疑问 / 已确认 / 已结算）、版本、操作。

| 操作 | 规则 |
|---|---|
| 出账 | 每月 3 日 02:00 自动生成上月账单；也可手动重新生成（版本 +1，原版本保留） |
| 处理疑问 | 查看合作社标注的订单行和说明 → 更正 → 重新出账 |
| 标记已结算 | 填打款日期、金额、上传凭证；金额与应结不一致必须写原因 |
| 导出 | 对账单 PDF（盖章用）和明细 Excel |

### A6-6 评价

**列**：商品、评分、内容、图片、机器审核结果（通过 / 疑似违规 + 命中词）、状态（待复核 / 已公开 / 已隐藏）、操作。人工复核通过才公开；隐藏需写原因。合作社在 H02 订单详情里能看到该单评价，可回复一条（≤100 字），回复同样进入本页复核后公开。

## B7 用户与服务

### A7-1 用户查询

**查询方式**：用户编号、订单号、收货手机尾号 + 订单日期、证件姓氏 + 后四位。不支持按完整证件号或完整姓名查询。

**用户详情**：基本（编号、昵称、注册时间、状态）、常用游客（张* · 后四位）、打卡记录、答题与分数、领礼记录、订单、反馈。所有个人信息脱敏。查看详情写日志（谁查了谁）。

**操作**：「标记异常」（暂停领礼资格，需写原因，用户端领礼时提示「请联系服务电话」）；「处理注销申请」（见 A7-6）。

### A7-2 问答库

字段：标准问题*、相似问法（多条，用于匹配）、答案*（≤150 字）、来源*（内容卡 / 公告 / 运营规则 / 服务信息）、关联页面（答案下方「去看看」按钮跳转）、类别（服务 / 文化 / 规则 / 安全）、审定状态。

**规则**：类别为「文化」的问答走 B3 审定链；「服务」「规则」类由运营直接上线（只涉及停车、厕所、开放时间、礼品规则等事实信息）。

### A7-3 未答问题

**列**：问题原文（合并相似后的代表问法）、出现次数、首次 / 最近出现、来源站点（如游客在站点页附近提问）、状态（待处理 / 已写答案送审 / 已上线 / 不处理）、操作。

**流程**：运营每周一处理 → 「写答案」生成问答库草稿（问题自动带入为标准问题，原始问法带入为相似问法）→ 走审定 → 上线后状态自动「已上线」。「不处理」需选原因（无关问题 / 不宜回答 / 重复）。

### A7-4 敏感词

**列**：词、类别（民族 / 宗教 / 政治 / 低俗 / 其他）、标准回复（选模板）、来源（民宗局指导 / 网信要求 / 运营补充）、启用状态。只有系统管理员和运营可编辑；改动写日志。标准回复模板见 05 号文件。

### A7-5 留言与纠错

**列**：类型（内容有误 / 功能问题 / 建议 / 表扬 / 投诉，与游客端 P30 一致）、内容、关联对象（纠错时为内容卡等）、提交时间、状态（待处理 / 处理中 / 已回复 / 已关闭）、处理人、操作。

**纠错流转**：内容纠错自动分派给该内容最后一个审定环节的单位，审定员在此看到并选：「无误，回复游客」/「确有错误，退回修改」（自动生成该内容的新版本草稿并通知运营）/「申请下线」。

**回复游客**：回复文字（≤200 字）发到游客「我的 → 意见反馈」，并发订阅消息（如游客授权过）。超过 3 个工作日未回复的进工作台红色提醒。

### A7-6 违规处置与注销

| 页签 | 内容 |
|---|---|
| 违规处置 | 记录：发现时间、对象、违规描述、处置（下线 / 隐藏 / 封禁）、是否已报告（报告对象、时间）；只追加 |
| 注销申请 | 用户在 P33 申请注销 → 7 天冷静期（用户可撤回）→ 自动执行：删除昵称头像、常用游客姓名与后四位，订单保留法定期限（脱敏），证件哈希保留至当年 12 月 31 日后删除（防止注销后重新领礼）；运营这里只查看，无需手动操作 |

## B8 数据看板

### A8-1 领导首页

一屏看完，每天 06:00 更新前一天数据，实时数据（今日）每 10 分钟刷新。

| 区域 | 指标（口径见 04 号第 9 节） |
|---|---|
| 顶部四卡 | 今日到访人数、今日领礼数、今日订单金额、问驮驮答上率；与上周同日比 |
| 四站对比 | 每站：到访、完成率、平均得分、领礼数、带动订单 |
| 走了几站 | 1 / 2 / 3 / 4 站人数分布（本年） |
| 礼品 | 各档领取人数、各柜台发放与库存 |
| 带货 | 订单数与金额趋势、按站带动、复购率、退款率 |
| 内容 | 审定覆盖率（应为 100%）、纠错数、下线数 |
| 安全 | 行驶中打卡被拦次数趋势 |

时间筛选：今日 / 近 7 天 / 近 30 天 / 本年 / 自定义。柜台主管只看本柜台；审定员只看内容区。

### A8-2 站点漏斗

每站：进入站点页 → 打卡成功 → 看完全部内容卡 → 答完 3 题 → 进入同心石榴 → 看商品 → 下单。每步人数与转化率，可按日期、渠道（`ch`）筛选。用于「内容是否站着能看完」的判断。

### A8-3 月度简报

每月 2 日自动生成上月简报（一页）：核心指标与环比、四站对比、礼品与库存、带货 Top5 商品与合作社、内容审定与纠错、问驮驮 Top10 未答问题、本月事件（公告、开放状态变化）。运营可在「本月说明」里加一段文字后「定稿」，导出 PDF。

### A8-4 数据导出

按指标导出 Excel，导出受权限控制、写日志；个人信息字段一律脱敏，不提供原始坐标（本来就没存）。
